调试器

调试器架构与命令实现

Windows 用户态调试器本质是一个异常处理框架：让被调试进程产生异常（断点、单步等），由系统捕获异常并通知调试器处理，从而控制程序执行流程。写一个调试器能把所有黑盒戳穿，深入理解异常机制、进程内存、线程上下文等底层概念。

调试器核心机制

两种调试模式

| 模式 | API | 说明 | |------|-----|------| | 运行调试 | CreateProcess + DEBUG_PROCESS / DEBUG_ONLY_THIS_PROCESS | 调试器主动创建被调试进程，从启动开始调试 | | 附加调试 | DebugActiveProcess | 对已运行的进程附加调试器 |

  • DEBUG_PROCESS：调试当前进程及其所有子进程
  • DEBUG_ONLY_THIS_PROCESS：只调试当前进程，不调试子进程

整体流程


CreateProcess(DEBUG_PROCESS) → WaitForDebugEvent → 事件分发 → ContinueDebugEvent → 循环
  • WaitForDebugEvent 阻塞等待调试事件，事件信息填入 DEBUG_EVENT 结构体
  • 根据 dwDebugEventCode 分发到对应处理函数
  • ContinueDebugEvent 放行被调试进程继续执行
  • 收到 EXIT_PROCESS_DEBUG_EVENT 后跳出循环

调试事件类型（9 种）

| 事件码 | 含义 | 返回值 | |--------|------|--------| | EXCEPTION_DEBUG_EVENT | 异常（断点/单步/访问违例等） | DBG_EXCEPTION_NOT_HANDLED（框架阶段） | | CREATE_PROCESS_DEBUG_EVENT | 创建进程 | DBG_CONTINUE | | CREATE_THREAD_DEBUG_EVENT | 创建线程 | DBG_CONTINUE | | EXIT_THREAD_DEBUG_EVENT | 退出线程 | DBG_CONTINUE | | EXIT_PROCESS_DEBUG_EVENT | 退出进程 | DBG_CONTINUE | | LOAD_DLL_DEBUG_EVENT | 加载 DLL | DBG_CONTINUE | | UNLOAD_DLL_DEBUG_EVENT | 卸载 DLL | DBG_CONTINUE | | OUTPUT_DEBUG_STRING_EVENT | 调试字符串输出 | DBG_CONTINUE | | RIP_EVENT | RIP 调试事件 | DBG_CONTINUE |

dwContinueStatus

  • DBG_CONTINUE：异常已处理，别往上抛，正常继续；对非异常事件只是"通知收到了，继续"
  • DBG_EXCEPTION_NOT_HANDLED：异常没处理，交给程序自己的异常处理链（SEH）接手

关键区分：非异常事件永远返回 DBG_CONTINUE（只是签收通知）；异常事件才需要判断，处理了返回 DBG_CONTINUE，没处理返回 DBG_EXCEPTION_NOT_HANDLED。

系统初始断点

被调试进程启动时，Windows 自动在 ntdll.dll 内部插入一个断点（INT 3，Code: 80000003）。这不是用户下的断点，是系统通知调试器"进程已加载完毕，准备执行用户代码"。所有被调试进程都会触发。

EXIT_PROCESS 后必须 break

被调试进程退出后不会再有事件，WaitForDebugEvent 会永远阻塞。收到 EXIT_PROCESS 事件后，ContinueDebugEvent 之后必须 break 出循环。

C 宏机制

宏 = 文本替换（填空）。预处理器在编译前完成替换，编译器看不到宏。两种宏：对象式宏（起别名）#define PI 3.14；函数式宏（带参数）#define DOUBLE(x) ((x)*2)。判断方法：宏名后面有没有紧跟括号，有括号 = 函数式，没括号 = 对象式。

变参宏


#define LOGI(fmt, ...) fprintf(stdout, "[%s]"fmt, __FUNCTION__, __VA_ARGS__)
  • ... 表示"剩下的参数"，必须是参数列表最后一个，前面至少有一个具名参数
  • __VA_ARGS__ 是变参占位符，展开时原样替换成剩余参数（带逗号）
  • ... 是"口袋"，不管塞几个全装进去，展开时整体倒出来

关键标识符

  • __FUNCTION__：编译器内置，展开成当前函数名字符串
  • __VA_ARGS__：配合 ... 使用的变参占位符
  • 双下划线前缀 = 系统保留的内置标识符

字符串字面量拼接

"[%s]"fmt：两个字符串字面量挨着写，编译器自动拼成一个。fmt 填进来的是带引号的字符串字面量，跟前面的 "[%s]" 拼成完整格式串。这是编译期完成的，不是运行时 strcat。

##__VA_ARGS__

## 是预处理器粘贴运算符。##__VA_ARGS__ 特殊用法：变参为空时，把前面那个逗号一起吃掉；变参有内容时 ## 不起作用，正常展开。

fprintf 与 stdout/stderr

  • printf(...) 固定往 stdout 打，是 fprintf(stdout, ...) 的简写
  • fprintf(流, ...) 指定输出流（stdout/stderr/文件）
  • stdout 带缓冲（攒一批再输出），stderr 不缓冲（立即输出）
  • 可分别重定向：> out.txt 只重定向 stdout，2> err.txt 重定向 stderr
  • 错误信息放 stderr 保证崩溃前能打出来

LOGE 宏的缺陷


#define LOGE(fmt, ...) fprintf(stderr, "[%s] ErrCode:%d "fmt, __FUNCTION__, GetLastError(), __VA_ARGS__)
  • GetLastError() 写死在宏内部，调用者无法干预；fprintf 内部 IO 可能改 last error，时机不可控
  • 没加 ##，空参时末尾多余逗号

调试器框架结构

数据段

  • g_DbgEvent DEBUG_EVENT <> — 事件结构体
  • g_si STARTUPINFO <> — 启动信息（CreateProcess 传入）
  • g_pi PROCESS_INFORMATION <> — 进程信息（CreateProcess 传出）
  • g_szBuf db 256 dup(0) — 日志缓冲区
  • g_szTarget db "路径",0 — 被调试程序路径（末尾只要 0，不要 13,10）

事件处理函数模式

每个事件函数：wsprintf 格式化信息到 g_szBuf → StdOut 输出 → 设 eax 为返回值（DBG_CONTINUE 或 DBG_EXCEPTION_NOT_HANDLED）→ ret。

事件循环结构


.while TRUE
    WaitForDebugEvent
    .if/.elseif 分发事件（调用处理函数，设 dwContinueStatus）
    ContinueDebugEvent
    .if EXIT_PROCESS → .break
.endw

DbgReadProcessMemory

封装 OpenProcess + ReadProcessMemory + CloseHandle，用于读取被调试进程内存（EventLoadDll 读 DLL 路径、EventDebugString 读调试字符串）。

EventLoadDll 两层间接读取

lpImageName 是指向指针的指针：第一次 ReadProcessMemory 从 lpImageName 读出 4 字节指针，第二次从指针读出字符串。fUnicode 判断字符串是 ANSI（%s）还是 Unicode（%ws）。

注意：第一个 DLL（ntdll.dll）的 lpImageName 读失败是正常的——系统在 CREATE_PROCESS 之前就加载了，不提供名字。

命令行架构


CreateProcess(DEBUG_PROCESS)
    → WaitForDebugEvent 事件循环
        → 9 种调试事件分发
            → EXCEPTION_DEBUG_EVENT 里处理断点/单步
                → 进命令循环 while(DbgGetCommand()==DBG_CMD)

返回值约定：

| 返回值 | 含义 | |--------|------| | DBG_ERR=0 | 错误 | | DBG_OK=1 | 退出命令循环，程序继续运行 | | DBG_CMD=2 | 继续留在命令循环等下一条命令 |

D、R、U、LM、设置断点等查看/设置命令返回 DBG_CMD；G、T、P 等需要目标执行的命令返回非 DBG_CMD。

软件断点机制

BREAKPOINT 结构体


BREAKPOINT STRUCT
    dwNum      DWORD ?  ; 序号
    dwAddress  DWORD ?  ; 地址
    bOriginal  DWORD ?  ; 原字节（按DWORD保存，恢复时只写1字节）
    dwType     DWORD ?  ; 0=一次性 1=永久
    dwState    DWORD ?  ; 0=删除 1=禁用 2=启用
BREAKPOINT ends

全局数组 g_bps BREAKPOINT 256 dup(<>)，256 个槽位。

DbgSetBreakPoint

1. ReadProcessMemory 读原字节 2. WriteProcessMemory 写 0xCC（g_bCC db 0CCh） 3. 遍历数组找 dwState==0 的空槽，填入地址/原字节/类型/状态=2

DbgFindBreakPoint

遍历数组按 dwAddress 匹配，返回 esi 指针 / 0。

ExecBreakPoint

1. 遍历断点数组，按 ExceptionAddress 匹配 2. 恢复原字节（只写回 1 字节） 3. EIP 回退 1（dec [ebx].regEip）——0xCC 命中后 EIP 指向 0xCC 后面 4. 永久断点（dwType==1）记录待恢复，设 TF 单步执行原指令，在单步异常中重打 0xCC；一次性断点不重打 5. .break 跳出遍历，进命令循环

软件断点生命周期


写0xCC → 命中时EIP回退1 → 恢复原字节 → 单步走过去 → 重打0xCC（永久断点）

命令行框架

命令表结构


COMMAND STRUCT
    cmd    DWORD ?  ; 命令字符串指针
    pFunc  DWORD ?  ; 函数指针
COMMAND ends

g_Cmds COMMAND <offset szCmdG,  offset CmdRun>
       COMMAND <offset szCmdR,  offset CmdShowRegs>
       COMMAND <offset szCmdDP, offset CmdBreakPoint>
       COMMAND <offset szCmdT,  offset CmdStep>
       COMMAND <offset szCmdU,  offset CmdDasm>
       COMMAND <0, 0>   ; 结束标记

每个 COMMAND 是连续但独立的数据声明，不用 \ 拼接（原因见文末踩坑）。

DbgGetCommand 流程

1. 打印 "cmd:" 提示 2. ReadConsole 读输入 → 截断末尾 \r\n（sub dwRead,2 后写 0） 3. 遍历字符串找空格，找到则把空格写 0（拆出命令名），esi 指向参数 4. 遍历命令表，lstrcmpi 不区分大小写比较（返回 0 表示相等） 5. 匹配到 → push esi（参数）+ call dword ptr [ebx].pFunc 6. 没匹配 → 打印错误，返回 DBG_CMD

注意：所有 Cmd 函数统一声明 args:DWORD，因为 DbgGetCommand 用 push esi 传了参数。

寄存器读写

DbgGetRegs / DbgSetRegs


OpenThread(THREAD_ALL_ACCESS, FALSE, dwThreadId)
  → 设 ContextFlags = CONTEXT_ALL
  → GetThreadContext / SetThreadContext
  → CloseHandle

每次用 g_DbgEvent.dwThreadId，函数内部 OpenThread + CloseHandle。

DbgShowRegs

分 3 次 wsprintf 打印（invoke 参数太多会报 statement too complex）：第 1 行 eax/ebx/ecx/edx/esi/edi，第 2 行 eip/esp/ebp/efl，第 3 行 cs/ss/ds/es/fs/gs。

CONTEXT 结构体字段：[esi].regEax、[esi].regEip、[esi].regFlag、[esi].regCs 等。

命令实现

g（CmdRun）


mov eax, DBG_OK   ; 退出命令循环，程序继续
ret

bp（CmdBreakPoint）


invoke htodw, args              ; MASM32库，十六进制字符串转DWORD
invoke DbgSetBreakPoint, eax, 1 ; 1=永久断点
mov eax, DBG_CMD                ; 留在命令循环
ret

t（CmdStep）


invoke DbgGetRegs, addr ctx
or [esi].regFlag, 100h    ; 设 Trap Flag（EFlags OR 0x100）
invoke DbgSetRegs, addr ctx
mov eax, DBG_OK           ; 退出命令循环，单步执行

单步后触发 EXCEPTION_SINGLE_STEP → ExecStep：显示寄存器 → 进命令循环。

u（CmdDasm / DbgDasm）

CmdDasm（命令入口）：


invoke htodw, args        ; 不带地址时htodw返回0
invoke DbgDasm, eax, 8    ; 反汇编8行
mov eax, DBG_CMD
ret

DbgDasm（反汇编核心）：

1. nAddress==0 时用 g_nPreAddress（继续上次） 2. ReadProcessMemory 读 0x1000 字节到 Code 缓冲区 3. 循环 nLine 次：Decode2Asm(pCode, szAsm, nCodeSize, nAddress) 反汇编一条 → wsprintf 格式化 "%08X %s" 打印 → pCode 和 nAddress 各加 nCodeSize 4. 循环结束后更新 g_nPreAddress

Decode2Asm 是 stdcall 4 参数：字节码指针、输出字符串、指令长度输出、指令地址。

dasm.lib 去 CRT 依赖

问题

  • dasm.lib（老师发的成品，MSVC 编译）依赖 LIBCMT.lib / uuid.lib
  • MASM32 自带 link 5.12（1998 年）找不到这些库，报 LNK1104
  • RadASM 配置里的 VS2022 路径是僵尸路径，实际没装；只有 VS2019

解决方案

1. 批量替换（sed \b 词边界，避免误伤已有的 lstrcpy/lstrcat）：strcpy → lstrcpyA，strcat → lstrcatA（kernel32，MASM32 已链接） 2. 手动改 Decode2Asm.cpp 4 处（无现成 API）：strstr(Opcode, ":") → 纯指针遍历找冒号；strncat(strAsmCode, &ch, 1) → 纯指针找末尾追加字符 3. ShowDecoded 的 printf 注释掉（函数无人调用，lib 按函数粒度链接不拉入） 4. memset.asm 汇编实现（编译器自动插入的 _memset，MSVC intrinsic 不能用 C 定义）：


.386
.model flat, c    ; 自动加下划线，写 memset → 符号 _memset
.code
memset proc
    push edi
    mov edi, [esp+8]     ; dst
    mov eax, [esp+12]    ; val (rep stosb 用 AL)
    mov ecx, [esp+16]    ; count
    test ecx, ecx
    jz short done
    rep stosb
done:
    mov eax, [esp+8]     ; return dst
    pop edi
    ret
memset endp
end

5. 编译命令：cl /c /O2 /GS- /Zl /nologo，打包 lib /OUT:dasm_clean.lib Decode2Asm.obj Disasm.obj Dsasm_Functions.obj memset.obj

  • /Zl：obj 不写 DEFAULTLIB:LIBCMT.lib
  • /GS-：去掉栈溢出保护 __security_cookie 符号

6. uuid.lib 拷到项目目录（DEFAULTLIB:uuid.lib 保险，实际无 GUID 引用不会拉入） 7. MyDebug.inc：includelib dasm.lib → includelib dasm_clean.lib

关键认知

  • /Zl 只去 LIBCMT 默认库，不去 uuid.lib（windows.h 的 #pragma comment(lib)）
  • 静态库按函数粒度链接：没被引用的函数不会被拉入
  • MSVC intrinsic 函数（memset/memcpy）C 层面不能定义，必须用汇编写
  • MASM .model flat,c 自动加下划线前缀：写 memset → 符号 _memset
  • 用 dumpbin /SYMBOLS 验证 obj 引用了哪些外部符号；/DIRECTIVES 验证 obj 的 DEFAULTLIB 指令

x86 调用约定

stdcall 要点：参数从右向左压栈，返回值在 EAX，被调用函数清理固定参数。

| 寄存器 | 类型 | 说明 | |--------|------|------| | eax | caller-saved | invoke 后值不确定 | | ecx | caller-saved | invoke 后值不确定 | | edx | caller-saved | invoke 后值不确定 | | ebx | callee-saved | invoke 后保证恢复 | | esi | callee-saved | invoke 后保证恢复 | | edi | callee-saved | invoke 后保证恢复 | | ebp | callee-saved | invoke 后保证恢复 |

注意：.while 循环里用 ecx/edx 做计数器，循环体有 invoke → 计数器被破坏 → 死循环崩溃，必须用 ebx/esi/edi。项目中部分自定义过程会修改 ESI，调用前后曾需要手工保存 ESI，长期应统一遵守调用约定。

MASM 语法与踩坑

结构体定义


结构名 STRUCT
    字段名 类型 ?
结构名 ENDS
  • 结构体变量声明用 <> 表示默认初始化（全零）：g_DbgEvent DEBUG_EVENT <>；结构体用 <>，不能直接写 0
  • 标量用值初始化：g_Count DWORD 0
  • UNION 用 UNION ... ENDS，各成员偏移从同一位置开始
  • 嵌套结构体从最底层开始定义，外层引用内层
  • assume esi:PTR BREAKPOINT 后用 [esi].field 访问结构体成员
  • SIZEOF 取结构体大小：add esi, SIZEOF BREAKPOINT

MASM32 头文件字段名坑

MASM32 头文件里字段名跟 C 头文件不完全一样：

| C 原名 | MASM32 名 | 说明 | |--------|-----------|------| | ExceptionRecord（EXCEPTION_DEBUG_INFO 里） | pExceptionRecord | 多了 p 前缀 | | nDebugStringLength | nDebugStringiLength | 多了一个 i（疑似头文件拼写错误） |

查字段名方法：在 masm32/include/windows.inc 里 grep 结构体名。

控制流伪指令

  • 有：.if / .elseif / .else / .endif、.while / .endw、.repeat / .until、.break
  • 没有 .switch，用 .if/.elseif 链代替

条件判断与内存操作

  • 逻辑或用 ||，逻辑与用 &&（or/and 是按位指令）
  • .if 里不能直接比较两个内存变量（x86 不支持 cmp mem, mem），先 mov 到寄存器再比
  • 内存不能直接对内存运算：add pCode, nCodeSize 报错 → mov eax, nCodeSize + add pCode, eax
  • .if/.while 中引用内存要加类型：byte ptr [esi] != 0

invoke 与 addr

  • invoke 自动压栈调用函数；addr 只在 invoke 里传参数时用，mov/lea 用 lea esi, ctx
  • 全局变量传地址用 offset，局部变量传地址用 addr
  • 函数参数声明指针一律用 DWORD
  • 函数指针调用要加 dword ptr：call dword ptr [ebx].pFunc
  • lstrcmpi 返回 0 表示相等（不是 1）
  • invoke 参数太多报 statement too complex：wsprintf 拆成多次调用
  • invoke SomeProc, eax, addr LocalVar 可能报 register value overwritten by INVOKE——展开 addr LocalVar 时可能使用 EAX，先把 EAX 保存到局部变量再传入

命令处理函数的栈平衡

命令分发器统一压入一个 args 参数，每个命令过程都应声明一个 DWORD 参数，即使该命令不用参数。否则 stdcall 返回时不会清理对应参数，ESP 会错位。

续行符与逻辑行长度

  • \ 用于 invoke 多行参数续行：参数之间要有逗号，最后一个参数后面不要逗号，\ 要在逗号之后
  • MASM 6.14 行长度有限，命令表用大量 \ 续行时会被拼成一条逻辑行，报 A2039: line too long——每个 COMMAND 作为连续但独立的数据声明，不再使用 \ 拼接

日志方案

  • wsprintf 是 user32 的，StdOut 是 MASM32 封装的，都不依赖 CRT
  • 需要 include masm32.inc + includelib masm32.lib
  • 汇编搞不了 C 那种变参宏，每个事件函数里手动 wsprintf + StdOut

proc 与 ret

  • 每个 proc endp 前必须有 ret，函数返回值在 eax
  • 用 call 调用无参函数，invoke 调用有参函数
