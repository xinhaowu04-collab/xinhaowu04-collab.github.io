程序结构与系统

子程序与栈帧

8086 的子程序机制围绕栈工作，CALL 压入返回地址，RET 弹出并跳回。调用约定（Calling Convention）是函数调用者与被调用者之间的一份二进制级契约，约定了参数如何传递、栈由谁清理、返回值如何存放、寄存器谁负责保存。

为什么要保存返回地址

如果不保存返回地址，用 JMP 跳转只能再加一个 JMP 跳回来，但是标号定死了，第二次跳转的时候就跳不回来了。


mov bp, sp
add sp, 2  ; 会被虚拟机污染，可以调回去再释放
jmp word ptr [bp]

但是代价有点大——为了保存返回地址，消耗了大量寄存器、大量标号。如果由 CPU 自动保存就可以省很多事。CALL 就是帮我们压栈，RET 就是回去。概念上等价于 PUSH 下一条指令地址 + JMP 目标，但 IP 寄存器不能直接通过 MOV 或 POP 操作——IP 只能通过跳转指令（JMP/CALL/RET/INT 等）间接修改。

其实 CALL 也是控制转移指令，跟 JMP 一样也是 CALL 偏移量（字节数）。

CALL

段内调用（近调用）：


CALL label      ; 直接调用，label 在同一段内
CALL reg        ; 间接调用，目标地址在寄存器中
CALL [mem]      ; 间接调用，目标地址在内存中

执行时只压入 IP：


SP = SP - 2
[SP] = IP（下一条指令的地址）
IP = 目标地址

段间调用（远调用）：


CALL FAR PTR label
CALL FAR [mem]

同时压入 CS 和 IP，顺序是先 CS 后 IP（IP 在栈顶）：


SP = SP - 2 ; [SP] = CS
SP = SP - 2 ; [SP] = IP
CS:IP = 目标地址

RET


RET             ; 近返回，弹出 IP
RET n           ; 近返回后再 SP = SP + n，用于清理参数

远返回需要与远调用配对：


RETF            ; 远返回，弹出 IP 再弹出 CS
RETF n

RET n 的 n 是字节数，用于调用者压栈参数后由被调用者清栈的约定（类似 stdcall）。例如压了 2 个字参数（4 字节），则 RET 4。

子程序的标准框架


my_proc PROC
    push bp
    mov  bp, sp      ; 建立栈帧
    ; 此时栈布局：BP+0=旧BP, BP+2=返回地址, BP+4=第一个参数, BP+6=第二个参数
    push ax          ; 保存要用到的寄存器（注意：保存后若用 SP 访问参数，偏移会变化）
    push bx
    ; 推荐做法：在 PUSH 保存寄存器之前先访问参数，或直接用 BP 计算偏移

    pop  bx
    pop  ax
    pop  bp
    ret
my_proc ENDP

BP 的作用是固定一个"帧基址"。SP 在子程序里会随 PUSH/POP 浮动，而 BP 不变，所以通过 [BP+偏移] 访问参数和局部变量是稳定的。

栈帧布局（近调用，调用者压参数）


高地址
┌─────────────────┐
│   参数 2        │ [BP+6]
│   参数 1        │ [BP+4]
│   返回地址(IP)  │ [BP+2]
│   旧 BP         │ [BP+0]  ← BP 指向这里
│   局部变量...   │ [BP-2], [BP-4]...
└─────────────────┘
低地址 (SP 在此附近)

远调用时返回地址占 4 字节（IP+CS），第一个参数在 [BP+6]。

几个关键细节

CALL 不影响标志位，RET 也不影响。

SP 必须对齐。CALL 前后 SP 的值必须保持一致，否则 RET 弹出的不是返回地址，程序直接飞掉。这是 8086 子程序调试时最常见的崩溃原因——PUSH 和 POP 数量不匹配。

寄存器保存约定。8086 没有强制的 ABI，但通常约定子程序保存 BP、SI、DI，而 AX、BX、CX、DX 可以自由使用（调用者不依赖其保留值）。

递归可以用，因为每次 CALL 都会在栈上分配新的返回地址和栈帧，天然支持嵌套。限制只有栈空间大小。

段内 vs 段间的选择在汇编时确定。如果子程序在同一代码段，用近调用；跨段用远调用，并且 PROC 定义时要标注 FAR：


my_proc PROC FAR
    ...
    RETF
my_proc ENDP

调用约定

核心差异：16位 vs 32位

| 项目 | 32位 x86 | 16位 8086 | |---|---|---| | 寄存器宽度 | 32位（EAX、ESP、EBP） | 16位（AX、SP、BP） | | 参数宽度 | DWORD = 4字节 | WORD = 2字节 | | 段寄存器 | 基本不用管（平坦内存） | 强制参与，近/远调用行为不同 | | 返回地址大小 | 近调用4字节，远调用6字节（CS 2B + EIP 4B） | 近调用2字节，远调用4字节 | | 调用约定 | stdcall/cdecl/fastcall | 只有近/远两种，无标准名称 | | fastcall | ECX/EDX传参 | 不存在，无寄存器传参约定 | | Win32 API | stdcall为主 | 不存在，对应DOS INT 21h | | 可变参数 | cdecl | 同样需要调用者清栈 |

两种调用类型总览

| 调用类型 | 参数宽度 | 返回地址占用 | 第一个参数偏移 | 谁清栈 | ret 形式 | |---|---|---|---|---|---| | 近调用（NEAR） | WORD = 2字节 | 2字节（只有IP） | [BP+04h] | 调用者或被调用者均可 | RETN / RETN N | | 远调用（FAR） | WORD = 2字节 | 4字节（IP+CS） | [BP+06h] | 调用者或被调用者均可 | RETF / RETF N |

栈帧布局详解

近调用，两个参数：


高地址
┌──────────────┐
│   参数2      │ [BP+06h]
│   参数1      │ [BP+04h]
│   返回地址   │ [BP+02h]  ← CALL 压入的 IP（2字节）
│   旧 BP      │ [BP+00h]  ← BP 指向这里
│   局部变量1  │ [BP-02h]
│   局部变量2  │ [BP-04h]
└──────────────┘  ← SP 在这里
低地址

远调用，两个参数：


高地址
┌──────────────┐
│   参数2      │ [BP+08h]
│   参数1      │ [BP+06h]
│   返回地址CS │ [BP+04h]  ← CALL FAR 压入的 CS
│   返回地址IP │ [BP+02h]  ← CALL FAR 压入的 IP（IP在栈顶）
│   旧 BP      │ [BP+00h]  ← BP 指向这里
│   局部变量1  │ [BP-02h]
│   局部变量2  │ [BP-04h]
└──────────────┘  ← SP 在这里
低地址

标准栈帧构建步骤

1. 调用者 PUSH 参数（从右到左） 2. CALL 指令将返回地址压栈（近调用压IP，远调用压CS再压IP） 3. 被调用者 PUSH BP 保存旧基址 4. 被调用者 MOV BP, SP 建立新帧基址 5. 被调用者 SUB SP, N 分配局部变量空间 6. 函数体执行 7. 被调用者 MOV SP, BP / POP BP 恢复 8. 被调用者 RETN N（近+被调用者清栈）或调用者 ADD SP, N（调用者清栈）

谁清栈

被调用者清栈（类似 stdcall）：函数内部用 RETN N 或 RETF N 一步完成返回和清栈，调用者无需任何操作。


; 调用者
push param2
push param1
call my_proc
; 返回后 SP 已恢复，不需要操作

; 被调用者（近调用，两个WORD参数 = 4字节）
my_proc PROC
    push bp
    mov  bp, sp
    ; ... 函数体 ...
    pop  bp
    retn 4          ; 返回 + SP += 4，清掉两个参数
my_proc ENDP

调用者清栈（类似 cdecl）：函数只做 RETN，调用者之后手动 ADD SP, N。适用于参数个数不固定的情况。


; 调用者
push param3
push param2
push param1
call my_varfunc
add  sp, 6          ; 调用者清栈：3个WORD = 6字节

; 被调用者
my_varfunc PROC
    push bp
    mov  bp, sp
    ; ... 函数体 ...
    pop  bp
    retn            ; 只返回，不清栈
my_varfunc ENDP

RETN N / ADD SP, N 中 N 的计算


N = 参数个数 × 2（每个WORD参数占2字节）

1个参数 → N = 2
2个参数 → N = 4
3个参数 → N = 6
4个参数 → N = 8

如果参数是双字（DX:AX对，32位数），每个参数占4字节，需手动累加实际字节数。

fastcall 不存在

8086 的通用寄存器（AX/BX/CX/DX）全部有隐含用途：

| 寄存器 | 隐含用途 | |---|---| | AX | MUL/DIV/IN/OUT，返回值 | | CX | LOOP，串操作计数 | | DX | MUL/DIV，I/O端口，高位扩展 | | BX | 间接寻址基址 |

没有空闲寄存器形成标准的寄存器传参约定，所有参数都走栈。

Win32 API → DOS INT 21h

8086 下没有 Win32 API，系统调用通过 DOS INT 21h 实现，使用寄存器传参，不涉及栈和调用约定：


; 32位（stdcall，压栈传参）：
push 0
push offset szTitle
push offset szMsg
push 0
call MessageBoxA@16     ; 函数内部 ret 16

; 16位（DOS中断，寄存器传参）：
mov  ah, 09h            ; 功能号 → AH
mov  dx, offset szMsg   ; 字符串地址 → DX（需 $ 结尾）
int  21h                ; 无需清栈

完整子程序示例

将两个参数相加，结果存 AX（近调用，被调用者清栈，类似 stdcall）：


; 调用方式：
;   push param2
;   push param1
;   call AddTwo

AddTwo PROC NEAR
    push bp
    mov  bp, sp          ; 建立栈帧

    mov  ax, [bp+04h]    ; 取参数1
    add  ax, [bp+06h]    ; 加参数2，结果在 AX

    pop  bp
    retn 4               ; 返回 + 清掉2个WORD参数
AddTwo ENDP

带局部变量的子程序：


MyProc PROC NEAR
    push bp
    mov  bp, sp
    sub  sp, 04h         ; 申请2个局部变量（2×2字节）
    push cx              ; 保存寄存器环境

    mov  cx, [bp+04h]    ; 取参数1
    mov  [bp-02h], cx    ; 存入局部变量1

    mov  cx, [bp+06h]    ; 取参数2
    mov  [bp-04h], cx    ; 存入局部变量2

    mov  ax, [bp-02h]    ; 准备返回值（AX = 局部变量1）

    pop  cx              ; 恢复寄存器环境
    mov  sp, bp          ; 释放局部变量空间
    pop  bp              ; 恢复旧BP
    retn 4               ; 返回 + 清栈
MyProc ENDP

标准栈帧销毁顺序：POP CX（恢复寄存器）→ MOV SP, BP（释放局部变量）→ POP BP（恢复栈底）→ RETN 4（返回+清栈）。顺序不能改，错了栈就乱了。

中断系统

8086 的中断系统是 CPU 响应内外部事件的标准机制，软件中断、硬件中断、异常三条路最终殊途同归，都走同一套"压栈保存现场→查表跳转→IRET恢复"的流程。

三条指令

INT n — 软件中断，n 是 0~255 的中断号。执行时依次做：


FLAGS 压栈
CS    压栈
IP    压栈（下一条指令的地址）
IF = 0（关闭可屏蔽中断）
TF = 0（关闭单步）
跳转到中断向量表第 n 项所指的地址

共压 6 字节（FLAGS 2 字节 + CS 2 字节 + IP 2 字节），这是和普通 CALL FAR 的关键区别——多压了一个 FLAGS。

INTO — 溢出中断，等价于：


; 伪代码
if OF == 1 then INT 4

OF 为 0 时是空操作。专门配合有符号运算使用，放在 ADD/SUB 之后检测溢出。

IRET — 中断返回，是 INT 的逆操作：


IP    弹出
CS    弹出
FLAGS 弹出（IF、TF 随之恢复）

只有 IRET 能正确从中断返回，普通 RETF 不恢复 FLAGS，导致 IF/TF 状态错乱。

中断向量表

8086 在物理地址 0000:0000 到 0000:03FF 存放 256 个中断向量，每个向量占 4 字节（IP 低字 + CS 高字），共 1KB。


物理地址 0x000：INT 0  的 IP（低字）
物理地址 0x002：INT 0  的 CS（高字）
物理地址 0x004：INT 1  的 IP
物理地址 0x006：INT 1  的 CS
...
物理地址 0x3FC：INT FFh 的 IP
物理地址 0x3FE：INT FFh 的 CS

查表公式：向量地址 = n × 4

CPU 收到中断号 n 后，从 0000:[n×4] 取 IP，从 0000:[n×4+2] 取 CS，组成目标地址。

栈帧布局

INT n 执行后，中断服务程序（ISR）入口处的栈：


高地址
┌──────────────┐
│   FLAGS      │ ← INT 压入
│   CS         │ ← INT 压入
│   IP         │ ← INT 压入，SP 指向这里
└──────────────┘
低地址

如果 ISR 内部还用了 PUSH BP / MOV BP, SP 建栈帧：BP+0=旧BP，BP+2=IP，BP+4=CS，BP+6=FLAGS，参数偏移从 [BP+08h] 开始（返回地址 IP+CS 共 4 字节 + FLAGS 2 字节 + 旧 BP 2 字节）。

常用中断号

| 中断号 | 来源 | 用途 | |--------|------|------| | INT 00h | CPU 异常 | 除零错误 | | INT 01h | CPU 异常 | 单步调试（TF=1时每条指令后触发） | | INT 02h | 硬件 NMI | 不可屏蔽中断（内存奇偶错等） | | INT 03h | CPU 异常 | 断点（0xCC，调试器用） | | INT 04h | CPU 异常 | 溢出（配合 INTO） | | INT 08h | 硬件 IRQ0 | 系统定时器（8253，约18.2Hz） | | INT 09h | 硬件 IRQ1 | 键盘 | | INT 10h | BIOS | 视频服务 | | INT 16h | BIOS | 键盘服务 | | INT 21h | DOS | DOS 系统调用（最常用） |

中断优先级和分类


不可屏蔽（NMI，INT 2）   ← 最高优先级，IF=0也响应
      ↓
内部异常（除零、溢出、单步、断点）
      ↓
可屏蔽硬件中断（INTR 引脚，IF=1才响应）
      ↓
软件中断（INT n）         ← 最低优先级

CLI（IF=0）只能屏蔽可屏蔽硬件中断，NMI 和内部异常无论如何都会响应。

几个关键细节

INT n 与 CALL FAR 的区别：CALL FAR 只压 CS:IP，INT n 额外压 FLAGS 并关闭 IF/TF。所以中断服务程序必须用 IRET 而不是 RETF 返回。

IF 在 INT 执行时自动清零。这意味着 ISR 执行期间默认不会被其他可屏蔽中断打断。如果需要允许嵌套中断，ISR 内部显式执行 STI 重新开中断。

INT 03h 的特殊编码：断点中断有单字节编码 0xCC，普通 INT n 是两字节（0xCD n）。调试器用 0xCC 替换目标地址的第一个字节来设置断点，命中后再恢复原字节，这就是软件断点的实现原理。

单步陷阱（TF）：INT 执行时 TF 清零，所以 ISR 本身不会被单步。调试器通过设置 TF=1 让 CPU 每执行一条指令就触发 INT 1，调试器的 INT 1 处理程序负责显示寄存器状态。

DOS 功能调用

DOS 功能调用是 8086 程序与操作系统交互的标准接口，全部通过 INT 21h 触发，用 AH 寄存器传功能号，其余寄存器按功能不同传参数，返回值通常在 AX。

调用约定


mov ah, 功能号      ; 必须
mov 其他寄存器, 参数 ; 按具体功能要求
int 21h             ; 触发
; 返回值在 AX 或指定寄存器
; CF=1 表示出错，AX 存错误码

DOS 功能调用不走栈传参，全程寄存器传递，没有清栈问题。

典型用法


; 输出单个字符（功能 02h），字符在 DL
mov ah, 02h
mov dl, 'A'
int 21h

; 输出字符串（功能 09h），字符串以 $ 结尾，地址在 DX
mov ah, 09h
mov dx, offset msg
int 21h

; 读键盘（功能 01h），字符返回在 AL
mov ah, 01h
int 21h             ; AL = 输入字符

; 程序退出（功能 4Ch），返回码在 AL
mov ah, 4Ch
mov al, 0
int 21h

几个关键细节

字符串终止符不同：09h 输出用 $ 结尾，文件名用 \0（ASCIIZ）结尾，0Ah 读入后数据区末尾是 0Dh（回车）。三种格式混用时最容易出错。

标准句柄：DOS 预定义了五个句柄，程序启动时直接可用：

| 句柄 | 含义 | |---|---| | 0 | 标准输入（键盘） | | 1 | 标准输出（屏幕） | | 2 | 标准错误 | | 3 | 标准辅助设备 | | 4 | 标准打印机 |

用 40h 写句柄 1 等价于在屏幕输出，写句柄 2 输出错误信息，这两个在重定向时行为不同。

DS 必须指向正确的段：09h 和 0Ah 用 DS:DX 寻址，如果 DS 不指向数据段，读写的是错误的内存。.COM 程序 DS=CS=ES=SS 天然对齐，.EXE 程序需要在入口手动设置 DS。

4Ch 之前不需要关闭句柄：DOS 在 4Ch 时会自动关闭所有打开的文件句柄。但养成显式关闭的习惯更好，特别是写操作后未关闭可能导致缓冲区未刷新丢数据。

BIOS 与 DOS 启动流程

这是从"机器通电"到"DOS 命令提示符出现"的完整链条，分成几个阶段交接。

通电复位

CPU 通电后，内部逻辑强制将寄存器设为固定初始值：


CS = FFFFh
IP = 0000h

物理地址 = FFFFh × 16 + 0000h = FFFF0h

这个地址在 ROM 的最顶端，只有 16 字节空间，放的是一条远跳转指令 JMP FAR，跳到 BIOS 主体代码的真正入口。这 16 字节叫做复位向量。

POST（加电自检）

BIOS 主体接管后，第一件事是 POST（Power-On Self Test）：

CPU 自检：执行几条基本指令验证 ALU 和寄存器是否正常。

内存检测：从低地址到高地址逐字节写入再读回，确认 RAM 可用容量和完整性。早期 BIOS 会在屏幕左上角显示内存计数，就是这一步。

芯片组初始化：配置 8237 DMA 控制器、8259 中断控制器、8253 定时器。其中 8259 把硬件 IRQ 映射到中断向量：


IRQ0（定时器）  → INT 08h
IRQ1（键盘）    → INT 09h
IRQ2            → INT 0Ah
...
IRQ7            → INT 0Fh

显卡初始化：检测显卡类型（MDA/CGA/EGA），初始化显示模式，之后才能在屏幕上显示内容。

其他硬件：键盘控制器、软驱控制器、串并口等逐一检测。

POST 出错时，因为显卡可能还没初始化，BIOS 用蜂鸣声报错（不同厂商蜂鸣码含义不同），这也是为什么硬件故障时电脑会"哔哔叫"。

中断向量表初始化

POST 完成后，BIOS 在物理地址 0000:0000 建立中断向量表，填写 256 个条目：


0000:0000  INT 00h 向量（除零）
0000:0004  INT 01h 向量（单步）
0000:0008  INT 02h 向量（NMI）
...
0000:0040  INT 10h 向量（视频服务）→ 指向 BIOS ROM 中的视频例程
0000:0058  INT 16h 向量（键盘服务）→ 指向 BIOS ROM 中的键盘例程
...
0000:0084  INT 21h 向量           → 此时还是空的，由 DOS 后续填写

BIOS 自己实现 INT 10h（视频）、INT 13h（磁盘）、INT 16h（键盘）等服务例程，把它们的地址写进向量表，之后这些服务就可以用了。

BIOS 数据区（BDA）

BIOS 在 0040:0000（物理地址 0400h）保留 256 字节作为 BIOS 数据区，存放运行时状态：


0040:0013  内存大小（KB）
0040:001A  键盘缓冲区头指针
0040:001C  键盘缓冲区尾指针
0040:001E  键盘缓冲区（32字节，循环队列）
0040:006C  定时器计数（INT 08h 每次+1，约18.2Hz）
0040:0049  当前显示模式
0040:004A  屏幕列数

这块区域是 BIOS 与上层软件共享状态的唯一渠道，DOS 和应用程序可以直接读写它。

引导加载（Bootstrap）

BIOS 完成初始化后，按照 CMOS 中配置的启动顺序（软驱→硬盘，或反过来）依次尝试每个设备，寻找可启动介质。

判断标准：读取设备第 0 磁道第 0 扇区（MBR，512字节），检查最后两个字节是否为 55h AAh（引导签名）。


扇区最后两字节：
偏移 1FEh = 55h
偏移 1FFh = AAh
→ 这是合法引导扇区

找到后，BIOS 把这 512 字节加载到物理地址 0000:7C00h，然后：


JMP 0000:7C00h    ; 控制权交给引导扇区代码

BIOS 的使命到此结束，后续完全由引导扇区代码负责。

引导扇区（MBR/Boot Sector）

以 DOS 为例，引导扇区是 DOS 格式化磁盘时写入的，它的任务：

读取 DOS 系统文件：在根目录找 IO.SYS（或 IBMBIO.COM）和 MSDOS.SYS（或 IBMDOS.COM），用 INT 13h 磁盘服务把它们加载进内存。

检查文件顺序：早期 DOS 要求这两个文件必须是根目录的前两个条目且连续存放，格式不对直接报 "Non-system disk"。


; 引导扇区伪代码逻辑
检查根目录前两个条目是否是 IO.SYS 和 MSDOS.SYS
如果不是 → 输出 "Non-System Disk" → 停机
如果是   → 用 INT 13h 把 IO.SYS 加载到 0070:0000
          → JMP 0070:0000

DOS 加载过程

IO.SYS（硬件抽象层）接管后：初始化设备驱动，把 BIOS 的 INT 13h 磁盘服务包装成 DOS 的块设备接口，建立 DOS 自己的设备驱动链。

MSDOS.SYS（DOS 内核）加载后：把 INT 21h 向量指向自己的服务入口——从这一刻起，INT 21h 才真正可用。同时建立文件分配表（FAT）缓存、内存分配表（MCB 链）、文件控制块（FCB）结构。

处理 CONFIG.SYS：


DEVICE=HIMEM.SYS
FILES=30
BUFFERS=20

每一行都在 DOS 内核初始化期间执行，加载驱动或设置参数。

加载 COMMAND.COM：DOS 内核最后加载命令解释器。COMMAND.COM 分两部分：常驻部分留在内存，暂驻部分可被覆盖（大程序运行后返回 DOS 时重新加载）。COMMAND.COM 处理 AUTOEXEC.BAT，执行其中的命令，最终显示：


C:\>_

完整链条


通电
  → CPU 跳 FFFF0h（复位向量）
    → BIOS POST（自检硬件）
      → 初始化中断向量表（INT 10h/13h/16h等）
        → 建立 BIOS 数据区（0040:0000）
          → 读 MBR，检查 55AAh 签名
            → 加载 MBR 到 7C00h，跳转执行
              → 引导扇区加载 IO.SYS
                → IO.SYS 初始化硬件驱动
                  → MSDOS.SYS 建立 DOS 内核，接管 INT 21h
                    → 处理 CONFIG.SYS
                      → 加载 COMMAND.COM
                        → 处理 AUTOEXEC.BAT
                          → C:\>

每一级只做自己分内的事，然后把控制权向下传。BIOS 不知道 DOS 是什么，引导扇区不知道 COMMAND.COM 是什么，各层之间只通过约定好的接口（固定地址、固定格式、固定中断号）交接。

直接调用 BIOS 中断

应用程序可以直接调用 BIOS 封装的函数（不同主板品牌不同）。BIOS 中断是固化在 ROM 里的一组服务例程，通过中断向量表对外暴露接口。应用程序和 DOS 本身都可以直接调用，是硬件抽象的第一层。

BIOS 中断与 DOS 中断的分工：BIOS 中断直接操作硬件，没有缓冲、没有文件系统概念；DOS 中断（INT 21h）在 BIOS 之上加了缓冲、路径解析、设备抽象。DOS 的磁盘文件操作最终调用 INT 13h，键盘输入最终调用 INT 16h。


; 改分辨率
xor ax, ax
int 10h
; 所有功能都很底层

学习路线：从 8086 到现代逆向

从逆向和底层安全方向看，BIOS 中断和 DOS 功能调用的实用价值有限，但它们建立了底层直觉：中断是怎么回事、调用约定为什么这么设计、栈帧为什么长这样。

值得深挖的路线：


Win32 API（user32/kernel32）
    → ntdll.dll（Native API）
        → SYSCALL 指令
            → Windows 内核（ntoskrnl）
                → 驱动模型（WDM/WDF）

以及围绕这条线的东西——PE 格式、IAT/EAT、调用约定（x64 的 fastcall 四寄存器约定）、异常处理（SEH/VEH）、反调试技术、加壳原理。
