节修改与代码注入

两种把注入代码纳入 PE 内存映像的思路：扩大最后一个节（不增节表项，把尾部数据并入已有节），或新增一个正式节（加一条节头，加载器按新节字段映射）。

扩大最后一个节

不增加节表项，把文件尾部追加的数据纳入原最后一个节的文件范围和内存范围。课堂流程：


1. 文件尾部追加注入数据
2. 处理最后节 VirtualSize（老师示例中清零）
3. 增大最后节 SizeOfRawData
4. 重新计算全局 SizeOfImage
5. 检查最后节 Characteristics 和控制流

第一步只改变文件长度；不改节头，新增数据仍只是 Overlay，加载器不必把它当节数据。

课堂算例

原最后节：


VirtualAddress   = 3000h
VirtualSize      = 0180h
PointerToRawData = 0600h
SizeOfRawData    = 0200h     ; 原节文件范围 0600h~07FFh，0800h 之后是原 Overlay

在 0800h 追加 250h 字节：


旧末端 0800h + 追加 0250h = 新末端 0A50h
AlignUp(0A50h, 200h) = 0C00h
新 SizeOfRawData = 0C00h - 0600h = 0600h

注入代码位置：


节内偏移 = 0800h - 0600h = 0200h
RVA      = 3000h + 0200h = 3200h
VA       = 00400000h + 3200h = 00403200h   （ImageBase=00400000h）

新内存范围与全局大小（按老师的 VirtualSize=0 兼容处理理解，有效内存大小约等于 SizeOfRawData）：


内存末端 = 3000h + 0600h = 3600h
SizeOfImage = AlignUp(3600h, 1000h) = 4000h

注意：

  • SizeOfImage 是可选头的全局字段，不是"最后一个节的 SizeOfImage"；节头改 VirtualSize/SizeOfRawData，可选头改 SizeOfImage
  • SizeOfRawData 按文件对齐后的整个节范围计算，不是只加注入长度
  • 标准做法是给 VirtualSize 设置足以覆盖新增内容的大小；老师的"清零"利用部分加载器/手动映射器对 VirtualSize=0 按 SizeOfRawData 处理的兼容行为，是课堂技巧、待样本验证，不是无条件规范
  • SizeOfRawData=0、VirtualSize=1000h 时文件无原始数据、内存零填，类似未初始化全局数据；反过来文件有数据而 VirtualSize 很小或为零时，不同加载器边界处理可能不同
  • 追加代码被映射不等于自动执行，还要让控制流跳到它
  • 最后节只有 R 或 RW、没有 X 时注入代码会因页面不可执行失败；复用数据节做代码区要改权限，带来兼容性和安全性问题

增加一个新节

新增正式节（如 .inj）：加一条 IMAGE_SECTION_HEADER，加载器按新节字段把新增数据复制到新内存区域。老师概括的步骤：


1. 修改 FileHeader.NumberOfSections
2. 检查节表是否有空间，必要时修改 SizeOfHeaders 和后续文件偏移
3. 插入一条新的节表项
4. 安排新节的文件位置、内存 RVA、大小和权限
5. 重新计算 SizeOfImage
6. 如需执行，再修改控制流

每条节头固定 40 字节（28h）。NumberOfSections 位于 IMAGE_FILE_HEADER 不是可选头；不更新它，加载器仍按旧数量遍历，看不到新节。

节表能否直接追加，取决于现有头部与第一个节原始数据之间有没有至少 28h 空余：

| 节表结束 | 第一节开始 | 空余 | 结论 | |---:|---:|---:|---| | 0340h | 0400h | C0h | 够放一条新节头 | | 03F0h | 0400h | 10h | 不够，需插入对齐空间、后移后续原始节数据并同步更新受影响的 PointerToRawData，必要时更新 SizeOfHeaders |

课堂算例

原最后节加载后末端 4800h，SectionAlignment=1000h：


新节 VirtualAddress = AlignUp(4800h, 1000h) = 5000h
VirtualSize   = 2000h    ; 占两个内存页
SizeOfRawData = 1000h    ; 只有一页文件初始化数据

含义：


RVA 5000h~5FFFh：文件中有一页初始化数据，加载时复制
RVA 6000h~6FFFh：文件中没有对应数据，加载时为零
内存末端 = 5000h + 2000h = 7000h
SizeOfImage = 7000h

新节表项概念值：


Name              = .inj
VirtualAddress    = 5000h
VirtualSize       = 2000h
PointerToRawData  = 文件尾部按 FileAlignment 对齐后的位置
SizeOfRawData     = 1000h
Characteristics   = 按用途设置

注意：

  • 新增节通常不用改 ImageBase；只有整体搬迁并处理重定位时才考虑
  • 改 SizeOfHeaders 不等于给节表腾空间：物理空间不够时还要插入/移动文件字节并修改后续 raw 偏移
  • 一个节表项的 Characteristics 是节级描述，不能单靠它把两页分别设成 RX 和 RW；代码页想 RX、工作缓冲区想 RW 时，分成两个节或运行时单独调整保护更清晰
  • 新节被加载不等于会执行，仍需入口点/跳转等控制流到达
  • SizeOfRawData=1000h 不代表两页文件内容：本例只有一页文件原始数据，第二页由 VirtualSize 描述并零填。"一页初始化、一页未初始化"省掉第二页的文件存储，代价是同节两页共享节级权限
