代码外提（体积优化）

  • 核心机制：当多个条件分支（如 if-else 或 switch-case）中包含完全相同或高度重复的指令序列时，编译器会将这部分公共代码从各个分支中剥离，提到分支之前（提前执行）或汇聚到分支之后的公共出口（延迟执行，也称 Tail Merging）。

// 优化前：
if (condition) {
    do_A();
    printf("done");
} else {
    do_B();
    printf("done");
}

// 优化后：
if (condition) {
    do_A();
} else {
    do_B();
}
printf("done");

减少流程转移

  • 核心机制：尽量减少指令流中的跳转指令（jmp、jxx），通过调整基本块布局让高概率执行的代码路径顺延直行（Fall-through）。
  • 优化目的：
  • 保护 CPU 流水线：跳转指令（尤其是条件预测失败时）会导致 CPU 清空流水线，带来严重的性能惩罚。
  • 提升缓存命中：让指令在内存中连续排布，大幅提升 L1 指令缓存（i-Cache）与预取效率。
  • 典型应用：
  • 在 if (A || B) 中，只要条件 A 成立直接 jge 跳到目标执行体；若 A 不成立，则直接顺延（Fall-through）到条件 B 的 cmp，若 B 成立再次直接顺延落入执行体，全程不需要额外的中间无条件跳转 jmp 衔接。

| | 跳转方向 | 共享点身份 | fall-through 的含义 | | ---------- | ------------------ | ----------- | ---------------- | | A && B | 条件假才跳，跳向体外 | 共享的逃逸出口 | A、B 全真 | | A \|\| B | 条件真就跳，跳向体内 | 共享的进入入口 | A 假，接着判 B |
