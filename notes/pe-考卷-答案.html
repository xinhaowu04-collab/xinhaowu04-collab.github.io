一、选择题答案

1. B - 0x4550（PE签名是"PE\0\0"的ASCII编码，0x50='P', 0x45='E'） 2. B - e_lfanew（DOS头偏移0x3C处，指向NT头的文件偏移） 3. A - DataDirectory[0]（IMAGE_DIRECTORY_ENTRY_EXPORT = 0） 4. B - DataDirectory[1]（IMAGE_DIRECTORY_ENTRY_IMPORT = 1） 5. B - FOA = PointerToRawData + (RVA - VirtualAddress)（文件偏移 = 节在文件的起始 + RVA在节中的偏移） 6. B - DataDirectory[5]（IMAGE_DIRECTORY_ENTRY_BASERELOC = 5） 7. C - IMAGE_REL_BASED_HIGHLOW（PE32常用，值为3，表示修正32位地址） 8. C - DataDirectory[13]（IMAGE_DIRECTORY_ENTRY_DELAY_IMPORT = 13） 9. C - DataDirectory[9]（IMAGE_DIRECTORY_ENTRY_TLS = 9） 10. B - 遇到全零描述符（20字节全为0的IMAGE_IMPORT_DESCRIPTOR标志结束） 11. C - RVA落在导出目录范围内（转发字符串存储在导出表内部） 12. B - 16位（WORD类型） 13. B - TypeOffset >> 12（高4位是类型，右移12位获取） 14. B - 遇到NULL指针（回调数组以NULL终止） 15. C - 文件正常结构末尾之外的数据（附加在PE文件尾部的额外数据）

三、判断题答案

1. × - 同一个RVA只对应一个FOA（RVA在映像中是唯一的，通过定位所属节转换为唯一的FOA）

2. × - ImageBase是首选加载基址，不一定是实际基址（ASLR会导致实际加载地址不同）

3. × - 可以只按序号导出，没有名称（NumberOfNames ≤ NumberOfFunctions）

4. √ - EAT[i]=0表示该序号位置无效，称为序号空洞

5. × - EXE也可能需要重定位表（尤其是启用ASLR时）

6. × - 在磁盘文件中通常指向相同的INT（都是RVA），但加载后FirstThunk会被改写为实际函数地址

7. × - 延迟导入的DLL在第一次调用其函数时才加载

8. √ - TLS回调在DLL_PROCESS_ATTACH和程序入口点之前执行

9. × - 需要修复IAT、节对齐、可能的压缩/加密等问题

10. × - 转发的RVA指向一个ASCII字符串（格式："DllName.FunctionName"），不是直接的函数地址

四、简答题答案

1. RVA、VA和FOA的区别和联系

定义：

  • RVA（Relative Virtual Address）：相对虚拟地址，相对于模块加载基址的偏移
  • VA（Virtual Address）：虚拟地址，进程地址空间中的绝对地址
  • FOA（File Offset Address）：文件偏移地址，在磁盘文件中的字节偏移

关系：


VA = ImageBase（实际加载基址）+ RVA
FOA = PointerToRawData + (RVA - VirtualAddress)

RVA转FOA的步骤：

1. 遍历节表，找到包含该RVA的节（VirtualAddress ≤ RVA < VirtualAddress + VirtualSize） 2. 计算RVA在该节内的偏移：Offset = RVA - VirtualAddress 3. 加上节在文件中的起始位置：FOA = PointerToRawData + Offset

注意事项：

  • 如果RVA在文件头范围内（< SizeOfHeaders），FOA = RVA
  • 如果RVA对应的内存区域在文件中没有数据（如.bss段），转换无效

2. 导出表按名称查找函数的流程

完整流程：

1. 在AddressOfNames中查找：遍历名称指针数组，比较每个RVA指向的字符串


   for (i = 0; i < NumberOfNames; i++) {
       if (strcmp(Name_i, "CreateFileA") == 0) break;
   }

2. 通过AddressOfNameOrdinals获取EAT索引：


   EAT_index = AddressOfNameOrdinals[i];  // WORD值

3. 通过AddressOfFunctions获取函数RVA：


   Function_RVA = AddressOfFunctions[EAT_index];

4. 计算导出序号（如果需要）：


   Ordinal = Base + EAT_index;

为什么不能直接用名称表下标访问EAT：

  • 名称表是稀疏的，可能有序号空洞（只按序号导出的函数）
  • 名称表的下标i不等于EAT下标
  • AddressOfNameOrdinals就是映射数组：名称表下标 → EAT下标
  • 例如：第3个名称（下标2）对应的函数可能在EAT[98]，而不是EAT[2]

图示：


名称表下标0 → NameOrdinals[0]=5  → EAT[5] → 函数1 RVA
名称表下标1 → NameOrdinals[1]=2  → EAT[2] → 函数2 RVA
名称表下标2 → NameOrdinals[2]=98 → EAT[98] → 函数3 RVA

3. 为什么Dump的内存映像不能直接运行

主要问题：

1. IAT已被修改：

  • 磁盘文件中IAT存放的是INT的RVA（或Hint+Name的RVA）
  • 内存中IAT已被加载器修改为实际函数地址
  • 这些地址在Dump文件中无效（依赖运行时的DLL加载地址）

2. 节对齐不同：

  • 内存中按SectionAlignment对齐（通常0x1000）
  • 磁盘文件按FileAlignment对齐（通常0x200）
  • Dump的内存布局直接写入文件会造成巨大浪费和对齐错误

3. 重定位问题：

  • 内存中的硬编码地址已经被重定位修正
  • Dump文件要重新加载到不同地址时需要原始的重定位表
  • 加壳程序可能已删除重定位表

4. 资源被解压或解密：

  • 加壳/压缩程序运行时解压代码和数据
  • Dump保存的是解压后状态，但文件结构仍指向压缩版本

修复方法：

1. 重建IAT：使用ImportREC等工具，遍历代码段中的call [IAT]，识别调用的API，重建导入表 2. 调整节对齐：将内存布局按FileAlignment重新组织，修改PointerToRawData和SizeOfRawData 3. 修复入口点：定位OEP（Original Entry Point），修改AddressOfEntryPoint 4. 重建或修复重定位表：如果需要ASLR，重新扫描代码段生成重定位信息

4. 延迟导入和普通导入的区别

普通导入（Static Import）：

  • 程序启动时加载所有依赖的DLL
  • 加载器解析所有导入函数，填充IAT
  • 如果某个DLL缺失或函数不存在，程序无法启动

延迟导入（Delay Import）：

  • 程序启动时不加载延迟导入的DLL
  • 第一次调用延迟导入函数时，通过thunk触发加载
  • 加载后将函数地址写入延迟IAT（类似普通IAT）

延迟导入的结构：


typedef struct _IMAGE_DELAYLOAD_DESCRIPTOR {
    DWORD Attributes;
    DWORD DllNameRVA;           // DLL名称
    DWORD ModuleHandleRVA;      // HMODULE存放位置
    DWORD ImportAddressTableRVA;// 延迟IAT
    DWORD ImportNameTableRVA;   // 延迟INT
    DWORD BoundImportAddressTableRVA;
    DWORD UnloadInformationTableRVA;
    DWORD TimeDateStamp;
} IMAGE_DELAYLOAD_DESCRIPTOR;

优势： 1. 启动速度快：减少启动时需要加载的DLL数量 2. 按需加载：某些功能不使用则对应DLL不加载，节省内存 3. 容错性好：延迟DLL缺失不影响程序启动，只在调用时报错

劣势： 1. 首次调用延迟：第一次调用会触发LoadLibrary和GetProcAddress，有性能开销 2. 运行时失败：DLL缺失会在运行时报错，而非启动时 3. 调试复杂：延迟加载机制增加了调试难度

使用场景：

  • 可选功能模块（如插件系统）
  • 大型程序优化启动时间
  • 条件依赖（如DirectX在游戏中）

五、结构分析题答案

1. IMAGE_EXPORT_DIRECTORY分析

  • EAT有多少个槽位：10个（NumberOfFunctions = 10）
  • 有多少个函数有名称：7个（NumberOfNames = 7）
  • EAT的第3项对应的导出序号：4（Base + EAT索引 = 1 + 3 = 4）
  • 如果某个函数的名称在名称表中的下标是5，如何获取其函数RVA：

  步骤1：读取 NameOrdinals[5]，假设值为 X
  步骤2：读取 AddressOfFunctions[X]，得到函数RVA
  步骤3：判断RVA是否在导出目录范围内
         - 如果在范围内，RVA指向转发字符串
         - 如果不在范围内，RVA是函数地址

2. IMAGE_BASE_RELOCATION分析

已知：00 30 00 00 18 00 00 00（小端序）

  • PageRva：0x00003000（前4字节，小端序）
  • SizeOfBlock：0x00000018（后4字节，小端序，十进制24）
  • 该块有多少个重定位条目：(24 - 8) / 2 = 8个
  • 如果第一个TypeOffset是0x3ABC，解析出Type和Offset：

  Type = 0x3ABC >> 12 = 0x3 = IMAGE_REL_BASED_HIGHLOW
  Offset = 0x3ABC & 0x0FFF = 0xABC
  完整RVA = PageRva + Offset = 0x3000 + 0xABC = 0x3ABC

  • PE签名（4字节："PE\0\0"）
  • 文件头（IMAGE_FILE_HEADER，20字节）
  • 可选头（IMAGE_OPTIONAL_HEADER，PE32是224字节）
  • 节表（每个节40字节 × 节数量）

通常按FileAlignment对齐后的大小。

七、综合应用题答案

场景：手动解析PE导出表

已知信息：

  • 加载基址：0x76D00000
  • 导出目录RVA：0x8A2E0
  • 导出目录大小：0x567

1. 导出目录的VA范围是？（2分）

答案：


起始VA = ImageBase + 导出目录RVA
       = 0x76D00000 + 0x8A2E0
       = 0x76D8A2E0

结束VA = 起始VA + Size
       = 0x76D8A2E0 + 0x567
       = 0x76D8A847

范围：0x76D8A2E0 ~ 0x76D8A847

2. CreateFileA的导出序号是多少？（2分）

答案：


导出序号 = Base + EAT索引
        = 1 + 98
        = 99

3. CreateFileA的函数VA是多少？（2分）

答案：


函数VA = ImageBase + 函数RVA
       = 0x76D00000 + 0x1D4F0
       = 0x76D1D4F0

4. 如何判断EAT[98]是函数地址还是转发字符串？（2分）

答案： 判断函数RVA是否落在导出目录范围内：


导出目录RVA范围：0x8A2E0 ~ 0x8A847

如果 0x8A2E0 ≤ RVA ≤ 0x8A847：
    RVA指向转发字符串（如"NTDLL.RtlAllocateHeap"）
否则：
    RVA是实际函数地址

本例中 0x1D4F0 < 0x8A2E0，所以是函数地址，不是转发。

5. 如果要按序号99直接获取函数地址，正确的计算步骤是什么？（2分）

答案：

步骤：


1. 验证序号有效性：
   if (序号 < Base || 序号 >= Base + NumberOfFunctions)
       return ERROR;  // 序号无效

2. 计算EAT索引：
   EAT_index = 序号 - Base
            = 99 - 1
            = 98

3. 读取EAT[98]：
   Function_RVA = AddressOfFunctions[98]
               = 0x1D4F0

4. 判断是否为转发（见上一题）

5. 计算函数VA：
   Function_VA = ImageBase + Function_RVA
              = 0x76D00000 + 0x1D4F0
              = 0x76D1D4F0

注意事项：

  • 序号导出可能有空洞（EAT[i] = 0），需检查
  • 必须先减去Base，因为序号从Base开始，而EAT索引从0开始
