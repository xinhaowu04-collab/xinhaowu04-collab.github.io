类与构造析构识别

类识别


  内存布局 = 结构体（成员按序排 + 对齐/padding）

  thiscall：ECX 传 this，其余参数走栈（x86）
    → 有无成员参数都先占 ECX，这是识别成员函数的关键

  例外与酌情还原：
    - 调用约定可被作者强改（一般不改）→ 还原时酌情
    - 函数被导出：即使改了约定，导出名（名称粉碎）
      仍暴露所属类，如 ??4MyClass@@QAEAAV0@ABV0@@Z
    - 无符号：按可读性自由选择 类 or 结构体

构造/析构识别


  构造：thiscall
    语法：对象生命周期内第一个被调 + 功能是初始化
    汇编：返回值 = this（MSVC 惯例，mov eax, ecx 收尾）

  析构：thiscall
    语法：最后一个被调 + 功能是释放资源
    汇编：返回 void

堆对象 new（release）


  ptr = operator new(sizeof)
  → 构造函数直接内联在 new 调用之后（不是 call ctor）
  → 识别：new 返回值立刻被初始化代码（内敛后的构造函数）使用

析构函数族（MSVC 生成三个变体）


  base dtor           ：只析构成员，不管内存

  deleting dtor       ：析构 + operator delete（无参）

  vector deleting dtor：带整型位标志参数：
      bit0: 是否 delete 内存
      bit1: 是否数组
      0 = 只析构         1 = 析构+delete单对象
      2 = 析构数组不删    3 = 析构数组+delete
  显式调用 obj.~T() 走 base dtor → 天然不会释放内存

  识别：析构函数带一个 0/1/2/3 的参数且内部 cmp/branch

对象数组（new[]）


  走"迭代器"函数（eh vector ctor/dtor iterator）

  参数：数组首地址、元素大小、个数、构造/析构函数指针
  Point ary1[3] 编译成两个循环：一循环调构造、一循环调析构
  内部含 SEH：第 N 个构造抛异常 → 自动析构已成功的 0..N-1
  → 看到 try/except 包着的构造循环 = 数组构造迭代器

全局对象生命周期


  构造：main 之前（CRT 动态初始化表 __xc_a~__xc_z，
        _initterm 遍历执行，同 int g = foo() 的机制）

  析构：main 返回之后——构造完成后编译器立刻生成
        atexit(&dtor) 注册；atexit 本质也是函数指针数组，
        exit() 时挨个回调

  推论：ExitProcess/TerminateProcess 强杀进程
        会跳过 exit 流程 → 全局对象不析构 → 资源泄漏
