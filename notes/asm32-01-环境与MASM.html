环境与 MASM

32 位汇编

环境与 MASM

MASM（Microsoft Macro Assembler）是微软的 x86 汇编工具链，包含汇编器 ml.exe 和链接器 link.exe，整个工具链位于 D:\masm32\ 目录，是经典的 Win32 汇编开发环境。

  • 汇编（Assembly）：把助记符指令（如 mov eax, 1）转成机器码，输出 COFF 格式的 .obj 文件
  • 链接（Linking）：合并一个或多个 .obj 与 .lib 库，解析外部符号引用（如 MessageBoxA 的地址），生成最终 .exe

/coff 标志让 ml.exe 输出 COFF 格式（Common Object File Format，Windows 标准目标文件格式，替代 16 位时代的 OMF）。不用 /coff 会输出 OMF，与 32 位链接器不兼容。

编译链接流程


D:\masm32\bin\ml /c /coff hello.asm
D:\masm32\bin\link /subsystem:windows /libpath:D:\masm32\lib hello.obj
  • /c：只编译不链接；省略则 ml 会直接调 link 完成完整构建
  • /coff：输出 COFF 目标文件，32 位 Windows 必须使用
  • /subsystem:windows：GUI 子系统，启动后不分配控制台窗口；误用 /subsystem:console 会让 GUI 程序多弹一个黑框
  • /libpath：库文件搜索路径，link 在此目录找 kernel32.lib、user32.lib 等导入库
  • 多个 .obj 或 .lib 以空格分隔依次列出

整体流程：hello.asm →（ml /c /coff）→ hello.obj（COFF）→（link + 导入库）→ hello.exe（PE）。

段（Segment）

程序在逻辑上划分为不同的段，每个段有独立的内存权限：

| 段 | 存放内容 | 内存权限 | 磁盘占用 | C 等价 | |----|----------|----------|----------|--------| | .code（或 .text） | 可执行指令 | 可读 + 可执行（RX） | 占 | 函数体 | | .data | 已初始化全局变量、字符串常量 | 可读 + 可写（RW） | 占 | int x = 42; | | .data?（或 .bss） | 未初始化全局变量 | 可读 + 可写（RW） | 不占 | int x;（全局） | | .const（或 .rdata） | 只读常量 | 只读（R） | 占 | const int x = 42; |

段的划分源于内存保护和程序组织两大需求：

1. 权限分离：代码不应被意外修改，数据不应被执行。CPU 通过段页式内存管理为不同区域设权限位，写 .code 段会触发 #GP（通用保护故障），OS 随即终止进程。 2. DEP / NX（W^X 策略）：同一页内存要么可写要么可执行，不能同时具备。攻击者把 shellcode 写进 .data 段后，因数据页不可执行，跳转会直接崩溃。 3. 磁盘与内存优化：.data? 段在 PE 文件中 PointerToRawData 和 SizeOfRawData 都设为 0，只占 VirtualSize。加载器检测到该节无原始数据，就在内存按 VirtualSize 分配并填零——这种机制叫零初始化节，所有未显式初始化的全局变量都归入此处，从而缩减 exe 体积。

段定义


.386                     ; 目标 CPU
.model flat, stdcall     ; 内存模型 + 调用约定

.data
szMsg    db "Hello, World!", 0
count    dd 42

.data?
buffer   db 1024 dup(?)   ; 1KB 缓冲区，不占 exe 空间

.const
MAX_SIZE equ 100          ; 常量

.code
start:
    ; 程序代码从这里开始
    ret
end start
  • flat：平坦内存模型，所有段在同一个 4GB 地址空间中，CS/DS/SS/ES 都指向同一基址，32 位 Windows 的标准模型
  • stdcall：默认调用约定为 stdcall（被调用者清栈），与 Windows API 一致

CPU 伪指令

伪指令声明目标 CPU 型号，在编译期做指令集验证：.386 下使用 cmov 会报 error A2070: invalid instruction operands。这相当于编译期静态断言，让汇编器不实际运行就能静态保证机器码在目标 CPU 上可执行，避免二进制分发后因 CPU 不兼容崩溃。

| 伪指令 | 对应 CPU | 年代 | 新增关键指令 | |--------|----------|------|-------------| | .386 | 80386 | 1985 | 32 位寄存器（eax/ebx/ecx/edx/esi/edi/ebp/esp）、保护模式、平坦内存模型 | | .486 | 80486 | 1989 | bswap（字节序反转）、xadd（交换并加） | | .586 | Pentium | 1993 | cpuid（CPU 信息查询）、rdtsc（读时间戳计数器） | | .686 | Pentium Pro | 1995 | cmov（条件传送）、为 SSE 奠定基础 | | .K3D | AMD 3DNow! | 1998 | AMD 专有的 SIMD 浮点指令 | | .MMX | Pentium MMX | 1997 | MMX 整数 SIMD（mm0~mm7 寄存器） | | .XMM | Pentium III | 1999 | SSE 浮点 SIMD（xmm0~xmm7 寄存器） |

Win32 窗口程序用 .386 即可覆盖所有基础 32 位指令。选择依据是程序实际使用的最"新"指令：


.386     ; 仅 32 位基础指令：mov/push/pop/call/ret
.586     ; 需要 cpuid 或 rdtsc
.686     ; 需要条件传送 cmovne
.XMM     ; 需要 SSE 浮点指令 movss/addss

数据类型

| 完整名称 | 缩写（步长） | 大小 | C 语言对应 | |----------|-------------|------|-----------| | BYTE | db（define byte） | 1 字节 | char | | WORD | dw（define word） | 2 字节 | short | | DWORD | dd（define double word） | 4 字节 | int、指针、HWND 等句柄 | | QWORD | dq（define quad word） | 8 字节 | long long、double |

db/dw/dd/dq 本质是步长声明：告诉汇编器每个元素占多少字节，连续排列时按此步长递增地址。


; 字符串（必须以 0 结尾才能被 Windows API 识别）
szTitle  db "My Window", 0
szHello  db "Hello, World!", 0      ; MessageBox 等 API 要求 \0 结尾

; 整数变量
counter  dd 0                       ; 32 位整数，初始化为 0
hwnd     dd ?                       ; 句柄变量，未初始化（运行时赋值）

; 缓冲区（dup 操作符批量分配）
buf      db 256 dup(0)              ; 256 字节全部初始化为 0
temp     db 128 dup(?)              ; 128 字节临时缓冲区，不初始化

; 数组（等价于 C: int arr[] = {1, 2, 3, 4, 5};）
arr      dd 1, 2, 3, 4, 5           ; 5 个 DWORD，共 20 字节

小端序

x86 用小端序存储多字节数据：低位字节存在低地址，高位字节存在高地址。8086 时代低字节在低地址的设计使 8 位和 16 位访存可复用地址线，简化硬件实现，后续 32/64 位扩展保持向后兼容。


.data
val dd 12345678h
; 内存里实际排列（低地址 → 高地址）：78 56 34 12

注意：调试器内存窗口看到 78 56 34 12，读成 DWORD 要反向拼成 0x12345678；调试器按 DWORD/WORD 显示时会自动处理好，但看原始字节流务必反向读。新手最常犯的错是把 78 56 34 12 误读成 0x78563412。

内存无类型

汇编中内存没有类型概念，只是一排连续字节，由指令决定如何解释。这源于冯·诺依曼架构的本质：数据和指令共享同一存储空间，内存单元本身不携带类型信息。

  • mov eax, [addr] —— 按 4 字节整数解释
  • mov al, [addr] —— 按 1 字节整数解释
  • fld dword ptr [addr] —— 按 32 位浮点数解释
  • call [addr] —— 按函数指针解释

与 C 的强类型相反，汇编器不验证也不关心你对内存的"用法"，一切决定权交给程序员。同一块内存可用不同步长读写，ptr 关键字临时指定操作数大小，是"告诉 CPU 你想怎么解释这块内存"的标准方式：


.data
myData dd 12345678h      ; 4 字节

.code
mov eax, myData               ; eax = 0x12345678（按 DWORD 读）
mov ax, word ptr [myData]     ; ax = 0x5678（低 2 字节）
mov al, byte ptr [myData]     ; al = 0x78（最低字节）
mov ax, word ptr [myData + 2] ; ax = 0x1234（跳过前 2 字节，高 2 字节）

关键伪指令

| 伪指令 | 作用 | |--------|------| | offset | 获取变量或标号的偏移地址（RVA），等价于 C 的 & 取地址符 | | end | 标记源文件结束 | | end start | 源文件结束 + 指定程序入口点为 start 标号 | | PROTO | 声明外部函数原型（参数个数和类型） | | INVOKE | 调用已声明的函数，自动生成参数压栈序列 | | MACRO / ENDM | 定义宏，在编译时展开为预定义的指令序列 |

offset

offset 在编译期计算变量相对于段基址的偏移（RVA，相对虚拟地址），常用于把变量地址传给 API。编译期即可确定，不生成额外指令，效率比 lea 高。


.data
szMsg db "Hello", 0

.code
push offset szMsg     ; 压入 szMsg 的地址（OFFSET 和 offset 写法不区分大小写）
call MessageBoxA

mov esi, offset szMsg ; esi 指向字符串首地址

end 与 end start

  • end 单独使用：仅告诉汇编器源文件到此为止。链接器会找默认入口点（WinMain 或 main），找不到报 error LNK2001: unresolved external symbol _WinMain@16
  • end start：指定 start 标号为程序入口点。标号名可任意（如 begin、entry），命名为 start 是约定俗成

.code
start:
    xor eax, eax
    ret
end start      ; 必须！指定入口点，否则链接失败

PROTO 与 INVOKE

手写 push + call 序列要求精确记忆参数个数和压栈顺序（从右往左压栈是 stdcall 和 cdecl 的共性）。INVOKE 是 MASM 的高级抽象：根据 PROTO 声明在编译期校验参数个数和类型，自动计算 push 序列（包括 ADDR 到 OFFSET 的转换），并按调用约定处理栈清理。


; 声明原型（通常在程序开头或包含文件中）
MessageBoxA PROTO, hWnd:DWORD, lpText:DWORD, lpCaption:DWORD, uType:DWORD
ExitProcess PROTO, uExitCode:DWORD

; 调用（ADDR 是 INVOKE 专用地址操作符，展开为 push offset；
; 在 INVOKE 上下文中 ADDR 和 OFFSET 可互换）
INVOKE MessageBoxA, 0, ADDR szMsg, ADDR szTitle, 0
INVOKE ExitProcess, 0

INVOKE 只是编译期文本展开，反汇编看到的是一串 push + call，最后一个参数最先压栈：


push 0                ; uType
push OFFSET szTitle   ; lpCaption
push OFFSET szMsg     ; lpText
push 0                ; hWnd
call MessageBoxA

注意：逆向看到"连续 push + call"且参数从右到左压栈，就是函数调用的标准模式，push 个数 = 参数个数。call 后紧跟 add esp, N → cdecl；call 后无清理且函数结尾是 ret N → stdcall。

MACRO 宏

宏在编译期展开，本质是文本替换，适合封装频繁使用的指令序列：


; 无参数宏
PRINT_EAX MACRO
    push eax
    push offset fmt
    call printf
    add esp, 8
ENDM

; 带参数宏
MyMacro MACRO param1, param2
    mov eax, param1
    add eax, param2
ENDM

MyMacro 10, 20    ; 展开为: mov eax, 10 / add eax, 20

宏被多次展开时内部标号会重名导致汇编错误，LOCAL 为每次展开生成唯一标号：


MyLoop MACRO count
    LOCAL loop_start          ; 声明局部标号
    mov ecx, count
loop_start:
    dec ecx
    jnz loop_start
ENDM

MyLoop 5
MyLoop 10
; 两次展开标号自动不同：第一次 loop_start$1，第二次 loop_start$2
