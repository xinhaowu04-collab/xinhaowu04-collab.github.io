工具与伪指令

Debug 调试与 COM 文件

Debug.exe 是 DOS 系统自带的交互式调试工具，可用于查看和修改内存、寄存器状态，以及编写和调试简单的汇编程序。COM 文件是 DOS 下一种简单的可执行文件格式，无文件头，代码从偏移 0100h 开始加载。

16 位汇编常见寄存器

通用寄存器：


AX    CX    DX    BX
SP    BP    SI    DI

AX = 累加器，几乎所有算术运算的默认目的地


MOV AX, 5       ; 被乘数放入 AX
MOV BL, 10      ; 乘数放入 BL
MUL BL          ; 结果在 AX（隐含）

CX = 计数器，循环和移位次数的默认寄存器


MOV CX, 10      ; 循环 10 次
LOOP_LABEL:
    ; 循环体
    LOOP LOOP_LABEL  ; CX--，CX≠0 时跳转

BP = 栈帧基址，函数调用时定位参数和局部变量


PUSH BP         ; 保存调用者的 BP
MOV BP, SP      ; BP = 当前栈顶，作为栈帧基址
MOV AX, [BP+4]  ; 访问栈上的参数
POP BP          ; 恢复调用者的 BP
RET

PUSH BP; MOV BP, SP 序列是函数入口的栈帧建立标志：后续 [BP+4]、[BP+6] 是访问函数参数，[BP-2]、[BP-4] 是局部变量。

控制/状态寄存器：


IP      指令指针（Instruction Pointer）
FLAGS   标志寄存器

段寄存器：


CS   代码段寄存器（Code Segment）
DS   数据段寄存器（Data Segment）
SS   栈段寄存器（Stack Segment）
ES   附加段寄存器（Extra Segment）

内存地址寻址能力

| 地址位数 | 支持的内存空间 | 地址范围 | |---------|---------------|---------| | 16位 | 64KB | 0x0000 ~ 0xFFFF | | 20位 | 1MB | 0x00000 ~ 0xFFFFF |

8086 的寄存器是 16 位的，但物理地址是 20 位的，所以需要"段:偏移"的分段机制来访问完整的 1MB 空间。


物理地址 = 段地址 × 16（左移4位） + 偏移地址


; 已知逻辑地址 CS:IP = 0DAB:0100
; 物理地址 = 0DAB × 10h + 0100 = 0DBB0h
; 注意不是 0DAB0100h！
  • 一个物理地址可以对应多个逻辑地址（多对一映射）：0000:0100 和 0010:0000 都指向物理地址 00100h
  • 段地址 × 16 在硬件上通过地址加法器左移 4 位实现，不是真乘法

程序的内存区域划分

| 区域 | 英文 | 对应段寄存器 | |------|------|------------| | 代码区 | Code Segment | CS | | 数据区 | Data Segment | DS | | 数据区（附加） | Extra Segment | ES | | 栈区 | Stack Segment | SS |

每个段寄存器配合特定的通用寄存器，构成默认的寻址组合：


CS : IP        代码段 : 指令指针
DS : BX / SI   数据段 : 基址/源索引
SS : SP / BP   栈段   : 栈指针/基址指针
ES : DI        附加段 : 目的索引

Debug 启动与寄存器状态解读


C:\>debug

启动后 CPU 各寄存器被初始化为特定值，例如：


AX=0000  BX=0000  CX=0000  DX=0000  SP=FFEE  BP=0000  SI=0000  DI=0000
DS=0DAB  ES=0DAB  SS=0DAB  CS=0DAB  IP=0100  NV UP EI PL NZ NA PO NC
0DAB:0100 0000          ADD [BX+SI], AL

解读：

  • CS=DS=ES=SS=0DAB：四个段寄存器指向同一个段，这是 .com 文件（单段内存模型）的典型特征。代码、数据和栈全部挤在由 0DAB:0000 开始的最大 64KB 物理内存块中
  • IP=0100：.com 文件的强制入口点偏移为 0100h（前 256 字节是 PSP）
  • SP=FFEE：栈指针指向段尾附近，栈向低地址增长

看 CS=DS=ES=SS 是否相等可以快速区分文件格式：相等是 .com 文件（单段模型），不等是 .exe 文件（多段模型）。

注意：DS=0DAB 这个值不是固定的，取决于 DOS 加载 Debug.exe 时分配的内存位置。不同机器、不同 DOS 版本启动后的段地址不同，但 IP=0100、SP=FFEE、CS=DS=ES=SS 这些关系是固定的。

FLAGS 标志位硬件解码

Debug.exe 使用专用双字母缩写表示 FLAGS 状态：

| 缩写 | 全称 | 对应硬件标志位 | 状态 | 逆向逻辑含义 | 反向缩写 | |------|------|--------------|------|------------|---------| | NV | No oVerflow | OF (溢出标志) | OF = 0 | 上一条有符号运算未发生溢出 | OV | | UP | UP (Direction) | DF (方向标志) | DF = 0 | 字符串拷贝方向为增量（正向） | DN | | EI | Enable Interrupt | IF (中断允许) | IF = 1 | 允许 CPU 响应外部硬件中断 | DI | | NG | NeGative | SF (符号标志) | SF = 1 | 结果为负数（最高位为 1） | PL | | NZ | Not Zero | ZF (零标志) | ZF = 0 | 运算结果不为零 | ZR | | NA | No Aux carry | AF (辅助进位) | AF = 0 | 未发生半字节进位 | AC | | PO | Parity Odd | PF (奇偶标志) | PF = 0 | 结果低 8 位中 1 的个数为奇数 | PE | | NC | No Carry | CF (进位标志) | CF = 0 | 未发生无符号进位/借位 | CY |

例如 Debug 中看到 NV UP EI PL NZ NA PO NC，逐字解读：无溢出、正向、中断开、正数、非零、无辅助进位、奇校验、无进位——上一条运算结果为正数且非零，无异常。

单步跟踪时重点看四个标志，覆盖 90% 的条件跳转判断：

1. NG/PL（SF）——结果是正还是负 2. NZ/ZR（ZF）——结果是否为零 3. NV/OV（OF）——有符号是否溢出 4. NC/CY（CF）——无符号是否进位/借位

注意：FLAGS 缩写是反直觉的。NG 表示结果为负（SF=1），PL 表示结果为正（SF=0）——NG = NeGative，PL = PLus，缩写不是首字母，需要对照表格记忆。

INT 20 汇编到源码逆向映射


0DAB:0000 CD20          INT     20

| 层面 | 解析 | |------|------| | 机器码 | CD 20 是 int 20h 的机器码 | | C 语言映射 | 等价于 C 标准库中的 exit(0)，告诉内核"程序运行结束，回收内存" | | 历史背景 | 比 int 21h, AH=4Ch 更古老的程序退出方式 |

PSP（程序段前缀）

Q：.com 文件的强制入口点是 0100，为什么 IP 停在 0000？

| 机制 | 说明 | |------|------| | PSP | DOS 在加载 .com 文件时，在 0000~00FF 的 256 字节中强制插入 PSP（Program Segment Prefix），存放命令行参数和环境变量指针 | | 防弹设计 | PSP 的第 0、1 字节被微软硬编码为 CD 20 (int 20h) | | 目的 | 容错机制：若程序员忘记写退出指令，CPU 跑飞绕回 0000 时自动触发 int 20h 安全退出，不会导致整个 DOS 系统死机 |

PSP 偏移量速查：


; PSP:0000  → CD 20 (int 20h) — 程序退出
; PSP:0080  → 命令行参数字符串
; PSP:000A  → 中断 22h 入口（程序结束地址）
; PSP:000E  → 中断 23h 入口（Ctrl+C 处理）

在 Debug 中看到偏移量在 0000~00FF 范围内且内容为 CD 20，说明这是 PSP 区域，不是代码。PSP 的偏移 0080h 处存放命令行参数。

注意：.com 文件入口必须是 0100h，不是 0000h。前 256 字节（0000~00FF）被 PSP 占用。如果误将入口点设为 0000h，CPU 会执行 PSP 中的 CD 20（int 20h），程序立即退出。

EU 与 BIU 整体框架

8086 在物理上分为两大部件：

| 部件 | 说明 | |------|------| | EU（执行部件） | 负责译码、运算，不直接连外部总线 | | BIU（总线接口部件） | 负责形成地址、读写外部总线、预取指令 |

| 部件 | 所属 | 作用 | |------|------|------| | 通用寄存器组 (AX/BX/CX/DX/SP/BP/SI/DI) | EU | 存放操作数 | | ALU | EU | 做加减乘除等运算 | | 标志寄存器 | EU | 保存运算结果状态（零标志、进位等） | | 段寄存器（CS/DS/SS/ES）+ IP | BIU | 存放地址信息（段基址、偏移），不存数据 | | 地址加法器 | BIU | 段地址 × 16 + 偏移地址 = 20 位物理地址 | | 指令队列缓冲器（6 字节） | BIU | 暂存预取来的指令字节，排队等 EU 取用 | | 输入/输出控制电路 | BIU | 管理与外部总线的实际读写 |

两条 16 位内部总线的分工：

  • 上面那条线：段寄存器/IP → 地址加法器，只负责算地址，不传输指令或数据本身
  • 下面那条线：EU 内部总线，负责指令译码和操作数运算，连接寄存器组、ALU、指令队列出口

BIU 会持续预取指令填充 6 字节队列，即使 EU 还没执行到。所以 Debug 单步时 -u 反汇编显示的指令可能比当前 IP 指向的更靠前——这是预取队列造成的"错觉"，实际执行顺序以 IP 为准。

典型数据流向：

① 寄存器间运算（不访问内存），如 ADD AX, BX：


AX、BX → 下面内部总线 → ALU 运算 → 结果回 AX，标志寄存器更新
（不经过段寄存器和地址加法器）

② 从内存读数据，如 MOV AX, [1234H]：


1. DS + 偏移 1234H → 地址加法器 → 算出 20 位物理地址（走上面的线）
2. 物理地址 → 外部地址总线 → 内存读出数据
   → 经输入/输出控制电路 → 外部数据总线
   → 下面内部总线 → 送入 AX 或 ALU

③ 写数据到内存，如 MOV [1234H], AX：


AX 的值（下面内部总线）+ DS 算出的地址（上面的线）
→ 一起通过外部总线 → 写入内存对应地址

取指流程：


1. CS + IP → 地址加法器 → 算出指令所在物理地址
2. 通过外部总线把指令字节取回
   → 输入/输出控制电路 → 指令队列缓冲器排队
3. 队列里的指令字节 → 下面内部总线 → 送入 EU 译码（不是送进 ALU 运算）
4. 译码后若需要操作数，操作数才真正进 ALU 运算

MZ 文件格式与 MASM

MZ（Mark Zbikowski，微软 MS-DOS 早期架构师的缩写）是 16 位 DOS 下的标准可执行文件格式。它引入了文件头和重定位表机制，允许操作系统将其动态加载到可用内存中，突破了 COM 文件单一段（64KB）的致命限制。MASM（Microsoft Macro Assembler）是用于编写 MZ 文件的汇编工具链。

为什么需要 MZ 格式

COM 文件无文件头，代码从 0100h 开始加载，CS=DS=SS=ES 指向同一个段，最大只能 64KB。8086 有 1MB 内存空间，COM 文件只能用 64KB，非常浪费。

MZ 格式引入了分段信息和数据代码分离机制，允许程序使用多个段，突破 64KB 限制。

文件格式的核心作用：


文件格式 = 告诉操作系统 CS:IP 的位置 + 分段信息
但不会帮你设置 DS、ES——必须自己在代码中设置

MZ 文件的物理结构与内存映射


文件偏移 (File Offset)                 内存布局 (Memory Layout)
0x0000 +-----------------------+       +-----------------------+
       | IMAGE_DOS_HEADER      |       | PSP (程序段前缀, 256B) | 操作系统动态创建
       | (固定长度, 现代为64B) |       +-----------------------+ <-- 加载基址
       +-----------------------+       |                       |
e_lfarlc>| 重定位表            | ===>  |       代码段 (CS)     |
       | (Relocation Table)    |       |                       |
       +-----------------------+       +-----------------------+
       | 头填充 (Padding)      |       |       数据段 (DS)     |
e_cparhdr>---------------------+       |                       |
       |                       |       +-----------------------+
       |   程序载荷 (Body)     | ===>  |       未初始化数据区  |
       |  (代码 + 初始数据)    |       |                       |
       |                       |       +-----------------------+
EOF    +-----------------------+       |       栈区 (SS:SP)    |
                                       +-----------------------+

加载核心步骤

1. 校验签名：读取前 2 个字节，必须是 0x5A4D（ASCII 字符 MZ） 2. 分配空间：读取 e_minalloc 和 e_maxalloc，向系统申请足够的内存 3. 执行重定位：根据 e_lfarlc 定位到重定位表。遍历表中的指针，将操作系统分配的实际段基址加到程序代码中需要修正的地方 4. 移交控制权：根据 e_cs 和 e_ip 设置代码入口，根据 e_ss 和 e_sp 初始化栈顶，开始执行

IMAGE_DOS_HEADER 结构体


typedef struct _IMAGE_DOS_HEADER {
    WORD   e_magic;                     // 0x00: 魔法数字 'MZ' (0x5A4D)
    WORD   e_cblp;                      // 0x02: 文件最后页的字节数
    WORD   e_cp;                        // 0x04: 文件页数 (每页 512 字节)
    WORD   e_crlc;                      // 0x06: 重定位项数量
    WORD   e_cparhdr;                   // 0x08: 头部大小 (以 16 字节的段为单位)
    WORD   e_minalloc;                  // 0x0A: 所需最小附加段
    WORD   e_maxalloc;                  // 0x0C: 所需最大附加段
    WORD   e_ss;                        // 0x0E: 初始的 SS 寄存器值 (相对值)
    WORD   e_sp;                        // 0x10: 初始的 SP 寄存器值
    WORD   e_csum;                      // 0x12: 校验和
    WORD   e_ip;                        // 0x14: 初始的 IP 寄存器值
    WORD   e_cs;                        // 0x16: 初始的 CS 寄存器值 (相对值)
    WORD   e_lfarlc;                    // 0x18: 重定位表在文件中的偏移地址
    WORD   e_ovno;                      // 0x1A: 覆盖层编号
    WORD   e_res[4];                    // 0x1C: 保留字
    WORD   e_oemid;                     // 0x24: OEM 标识符
    WORD   e_oeminfo;                   // 0x26: OEM 信息
    WORD   e_res2[10];                  // 0x28: 保留字
    LONG   e_lfanew;                    // 0x3C: 指向 PE 头的文件偏移
} IMAGE_DOS_HEADER, *PIMAGE_DOS_HEADER;

e_lfanew 是 MZ 头中最核心的逆向字段——通过 MZ 头定位 PE 头（现代逆向标准范式）：


PIMAGE_DOS_HEADER pDosHeader = (PIMAGE_DOS_HEADER)fileBuffer;
if (pDosHeader->e_magic != IMAGE_DOS_SIGNATURE) return;
LONG peHeaderOffset = pDosHeader->e_lfanew;  // 偏移 0x3C
PIMAGE_NT_HEADERS pNtHeaders = (PIMAGE_NT_HEADERS)(fileBuffer + peHeaderOffset);

内存中出现 4D 5A（MZ 签名）说明找到了一个完整的可执行模块基址。脱壳和内存 Dump 时，MZ 签名是定位模块基址的关键信号。恶意代码中除了 e_magic 和 e_lfanew，中间 58 字节可能被篡改。

与 COM、PE 格式对比

| 对比维度 | COM 格式 | MZ 格式 | PE 格式 (现代 Windows) | |---------|---------|---------|----------------------| | 文件签名 | 无 (纯机器码) | MZ (0x5A4D) | MZ 头 + PE\0\0 | | 体积限制 | 严格 <= 64KB | 受限于常规内存 (~640KB) | 几无限制 | | 段支持 | 单一段 (CS=DS=SS) | 多段独立 (CS/DS/SS 分离) | 平坦内存模型 | | 现代逆向价值 | 编写 Shellcode 理论 | 仅作为定位 PE 头的"跳板" | 核心分析对象 |

手写 MZ 文件的完整步骤


; 第一步：分段
data segment
    text  db "hello word$"  ; db = define byte，定义字符串
    ; 汇编器提供标号（如 text）代替硬编码偏移量
    db 512 dup(0AAH)        ; dup = duplicate，重复 512 个 0AAH
    ; ? 表示未初始化（分配空间但不填值，内容不可预测），0 表示显式初始化为零
    ; h 表示 16 进制，b 表示 2 进制，默认 10 进制
data ends

Stack segment STACK  ; 栈段，STACK 参数告诉汇编器这是栈段
    ; 栈向下生长（向低地址），PUSH 时 SP 减小，POP 时 SP 增大
Stack ends

code segment
    start:          ; 告诉 ML 从这里开始拷贝代码
    ; 设置段寄存器
    mov ax, data
    mov ds, ax
    mov es, ax
    mov ax, stack
    mov ss, ax

    mov ah, 09h
    mov dx, offset text   ; offset 告诉编译器计算出偏移量
    ; lea dx, text        ; 第二种写法，直接取地址
    int 21h               ; COM 会直接结束，但 MZ 要用中断

    ; exit(0)
    mov ax, 4c00h         ; MZ 文件标准退出方法
    int 21h
    ret
end start           ; 告诉汇编器代码结束
code ends

注意：以字母开头的十六进制数前必须加 0（如 0AAH），否则 aah 会被识别为标识符（变量名/标号）而非数值。

编译链接（虚拟机 XP 中，已安装 MASM 并配置环境变量）：


ml /c hello.asm          ; 编译为 hello.obj（真机环境要加 coff）
link hello.obj           ; 链接为 hello.exe

硬盘扇区为 512 字节，读一个扇区跟读 512 字节速度相同，所以段最好是 512 的倍数。MZ 文件头和数据段之间有大块填充空间。可以用 align 设置对齐值。

栈的设置：定义栈内容没意义，但栈大小有意义：


link /stack:512 hello.obj  ; 设置栈大小为 512 字节

不自己定义栈时，链接器会把栈自动放在数据段上面（栈向下生长，所以 DS 和 SS 可以指向同一个地址——数据从低地址往高地址用，栈从高地址往低地址用，两者背靠背共享同一段空间），文件会更小更省空间。

通过 MZ 头定位 PE 头（完整 C 代码）


#include <windows.h>
#include <stdio.h>

void ParsePEFile(unsigned char* fileBuffer) {
    PIMAGE_DOS_HEADER pDosHeader = (PIMAGE_DOS_HEADER)fileBuffer;

    if (pDosHeader->e_magic != IMAGE_DOS_SIGNATURE) {
        printf("Error: 不是有效的 MZ/PE 文件！\n");
        return;
    }

    LONG peHeaderOffset = pDosHeader->e_lfanew;
    PIMAGE_NT_HEADERS pNtHeaders = (PIMAGE_NT_HEADERS)(fileBuffer + peHeaderOffset);

    if (pNtHeaders->Signature == IMAGE_NT_SIGNATURE) {
        printf("成功找到 PE 头！偏移位置: 0x%X\n", peHeaderOffset);
    }
}

伪指令专题

这几个不是孤立的，它们是一套——全都是围着 MACRO 转的。宏是 MASM 里唯一带"控制流"的伪指令机制，这几个就是宏的骨架。

先理解宏是什么

宏就是编译期的文本替换 + 简单编程。你定义一段代码模板，传参数进去，汇编器帮你展开成真实代码。和 C 的 #define 宏是一回事，语法不同而已。


MyMacro MACRO param1, param2
    ; 这里写模板代码
ENDM

MACRO 开始定义，ENDM 结束定义。这俩是一对，就像 C 的 { }。

六个关键字的角色

| 关键字 | 在宏里的角色 | 类比 | |--------|------------|------| | MACRO | 开头，声明宏名和参数 | #define FUNC(x) 的开头 | | ENDM | 结尾 | } 闭合 | | LOCAL | 声明宏内的局部标签 | 函数里的局部变量 | | EXITM | 中途提前退出宏 | return | | GOTO | 在宏内跳转 | goto | | PURGE | 删除已定义的宏 | 取消定义 |

MACRO + ENDM（定义宏）


SaveRegs MACRO
    push rax
    push rcx
    push rdx
ENDM

之后写 SaveRegs，汇编器就替换成那三条 push。参数也行：


AddConst MACRO reg, val
    add reg, val
ENDM

; 调用：AddConst rax, 5  →  展开成 add rax, 5

注意：宏在编译期展开，不是运行期调用。每次写一次宏名，就原地展开一份代码。写三次就展开三份——和函数调用不一样，函数只有一份代码。所以宏省了调用开销，但增大代码体积。

LOCAL（宏内局部标签）——最容易踩坑的

问题场景：宏里有标签，宏被调用多次，标签就会重复定义，编译报错。


; 这个宏有 bug
AbsVal MACRO reg
    cmp reg, 0
    jge positive
    neg reg
positive:
ENDM

调用两次 AbsVal rax / AbsVal rbx，展开后出现两个 positive: 标签——重复定义，报错。

LOCAL 解决这个：


AbsVal MACRO reg
    LOCAL positive          ; ← 声明局部标签
    cmp reg, 0
    jge positive
    neg reg
positive:
ENDM

汇编器每次展开时，会自动给 positive 生成唯一名字（比如 ??0000、??0001），不冲突。

规则：宏里只要出现标签，一律用 LOCAL 声明。LOCAL 必须紧跟在 MACRO 之后、其他指令之前写。

EXITM（提前退出宏）

像 return，在宏展开过程中遇到 EXITM 就停止展开，后面的内容不要了。


SafeDiv MACRO a, b
    IF b EQ 0               ; 如果除数是 0
        EXITM               ; 不展开后续代码
    ENDIF
    mov rax, a
    mov rcx, b
    xor rdx, rdx
    div rcx
ENDM

常配合条件编译 IF/ENDIF 用，根据参数决定要不要展开整段代码。

GOTO（宏内跳转）

在宏内部跳到某个 LOCAL 标签。注意：这个跳转发生在编译期宏展开过程中，不是运行期的跳转。用途很少，主要是配合 EXITM 做宏内的流程控制，比如根据参数走不同的展开路径。


Choose MACRO n
    LOCAL skip1, skip2
    IF n EQ 1
        GOTO skip1
    ENDIF
    ; n!=1 时展开的代码
    EXITM
skip1:
    ; n==1 时展开的代码
ENDM

GOTO 在宏里属于冷门功能，多数人写宏一辈子都用不到它，IF/ELSE/ENDIF 加 EXITM 就够控制流程了。

PURGE（删除宏）

取消一个已定义的宏，之后不能再调用它。


SaveRegs MACRO
    push rax
ENDM

SaveRegs            ; 能用

PURGE SaveRegs      ; 删掉

SaveRegs            ; 报错，未定义

场景很窄，主要用在：同一个宏名在不同阶段需要重新定义，或者防止宏被意外调用。日常几乎不用。

宏的一句话总结

  • MACRO/ENDM 管定义的起止
  • LOCAL 管标签冲突（高频，必会）
  • EXITM 管提前终止展开
  • GOTO 管编译期流程跳转（冷门）
  • PURGE 管删除宏定义（冷门）

实际写宏，MACRO/ENDM/LOCAL 三个是主力，后三个知道存在就行。

STRUCT + ENDS（结构体）—— 一对

就是 C 的 struct。STRUCT 开头，ENDS 结尾。


Point STRUCT
    x   DWORD ?
    y   DWORD ?
Point ENDS

声明变量：


    p1 Point <10, 20>        ; 初始化 x=10, y=20
    p2 Point <>              ; 默认值（0）

访问字段用 .：


    mov eax, p1.x            ; 取字段
    mov p1.y, 99             ; 写字段

和 C 完全一样，字段在内存里顺序排列。ENDS 就是闭合用的，没别的意思。MASM 里 STRUC 和 STRUCT 是同一个东西（旧版写 STRUC，新版 STRUCT），闭合都用 ENDS。

UNION（联合体）

C 的 union，所有字段共享同一段内存，大小取最大那个。


Value UNION
    b   BYTE ?
    w   WORD ?
    d   DWORD ?
Value ENDS

Value 大小是 4 字节（最大字段 d）。b/w/d 都从同一地址开始，改一个就影响全部。


    v Value <>
    mov v.d, 0x12345678
    mov al, v.b              ; al = 0x78，小端最低字节

用法和 C union 一模一样。

RECORD（位域）

C 里没有直接对应（C 的位域是 struct 里写 :n），MASM 单独给了个伪指令。用来把多个小字段塞进一个整数里。


; 把一个 BYTE 拆成三段
Color RECORD
    red   3:?,        ; 3 bits
    green 3:?,        ; 3 bits
    blue  2:?         ; 2 bits

初始化时按位填：


    c Color <5, 2, 1>         ; red=5, green=2, blue=1

MASM 会自动帮你做位拼接和掩码，访问字段时生成带掩码的 shift 指令。

RECORD 在实际写汇编时很少用，多数人直接手动 shift/and/or 处理位域更直观。属于"知道存在就行，用的时候再查"的东西。

TYPEDEF（类型别名）

就是 C 的 typedef。给已有类型起个新名字。


    LPFN TYPEDEF PTR DWORD      ; LPFN = 指向 DWORD 的指针
    HANDLE TYPEDEF DWORD        ; HANDLE = DWORD 的别名

之后可以当类型用：


    h HANDLE ?
    p LPFN ?

Win32 汇编里特别常见——Win32 API 的类型名（HANDLE、LPVOID、LPCSTR）在 C 里是 typedef，到了汇编就得用 TYPEDEF 重新定义一遍。

类型定义速记对照

| MASM | C 语言 | 用途 | |------|--------|------| | STRUCT/ENDS | struct | 定义结构体 | | UNION | union | 定义联合体 | | RECORD | 位域 | 位字段打包 | | TYPEDEF | typedef | 类型起别名 |

核心就 STRUCT/UNION/TYPEDEF 三个，和 C 完全对应。RECORD 冷门，了解即可。

ASSUME

ASSUME 是 MASM 伪指令，有点特殊——它不生成任何代码，纯粹是"告诉汇编器一声"：接下来，段寄存器 X 关联的是 Y 段/类型。汇编器知道了这个，才能帮你做字段偏移计算和类型检查。

最经典的场景是配合段使用：


ASSUME DS:DATA        ; 告诉汇编器：DS 现在指向 DATA 段

之后你写 mov eax, var，汇编器就知道 var 在 DS 指向的段里，能算出正确偏移。

为什么感觉"没用"：在简化段模型（.model flat / .data / .code）下，MASM 自动帮你 ASSUME 好了，根本不用手写。现代 Win32 汇编几乎全是 flat 模式，所以 ASSUME 基本不出现。它真正活跃的地方是完整段定义（SEGMENT/ENDS）和老式 16 位 DOS 汇编，那里段寄存器要手动管，必须 ASSUME 告诉汇编器当前状态。

另一个常见用途：给寄存器套类型——让汇编器把某个寄存器当成结构体指针：


ASSUME ecx:PTR Point      ; 告诉汇编器：把 ecx 当 Point 结构体指针
mov eax, [ecx].x          ; 现在能直接用 .x 访问字段
mov [ecx].y, 99
ASSUME ecx:NOTHING        ; 用完取消，别让汇编器继续误判

不写 ASSUME 的话，[ecx].x 会报错——汇编器不知道 ecx 指向什么类型，没法算 .x 的偏移。

关键点：用完一定要 ASSUME ecx:NOTHING 取消，否则后面 ecx 被当成别的用途时汇编器会报类型错误。这是它唯一的实际用途。

关于结构体传参：局部变量可以直接访问结构体成员；全局变量和参数不可以，必须用 ASSUME。所以一般函数参数不喜欢传结构体，不如直接传指针。
