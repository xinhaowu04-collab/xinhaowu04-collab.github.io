重载静态成员与继承

重载函数与运算符重载识别


  无符号：重载只是几个不同的函数地址，语法层信息全灭
    → 只能靠功能逻辑人工归类
      （operator= 特征：返回值是 *this 引用、内部逐成员拷贝）

  有符号：名称粉碎白送类名和参数
    ??4MyClass@@QAEAAV0@ABV0@@Z = MyClass::operator=

  优化干扰：运算符重载常被内联
    → 汇编里看不到 call，只剩"逐成员对称运算"的形状

静态成员变量


  编译后 = 全局变量
    → 不占对象内存，对象布局里找不到它

  二进制里看不到"类作用域"，只能按相关性推断：
    - 被同一批成员函数反复访问的全局变量
    - 初始化出现在 CRT 动态初始化表（同全局对象机制）
    - 功能与类强相关（实例计数器、共享句柄之类）

继承·内存结构（x86，x64 指针偏移翻倍）


  Base:
    +00 vptr → Base_vftable { Base::vfun1, Base::vfun2 }
    +04 Base::member

  Derived:
    +00 vptr → Derived_vftable { Derived::vfun1,   ← 重写的槽被覆盖
                                  Base::vfun2,      ← 没重写原样继承
                                  Derived::vfun3 }  ← 新增虚函数追加表尾
    +04 Base::member     ← 基类成员做前缀
    +08 Derived::member  ← 新增成员追加在后

  单继承：一个 vptr、一张虚表、this 全程不调整

构造/析构顺序


  构造：基类构造 → 填派生虚表 → 成员初始化 → 构造函数体
    mov ecx, this
    call Base_ctor                ; 基类构造（内部写基类虚表）
    mov [ecx], offset Derived_vt  ; 覆盖为派生虚表
    ...成员初始化...

  析构严格逆序：函数体/成员析构 → 恢复基类虚表 → 调基类析构

  区分基类构造 vs 成员构造（难点）：
    基类构造：this 原样传入，写虚表在 [this+0]
    成员构造：lea ecx, [this+N]，传的是成员子对象地址

继承·汇编特征清单


  ① 填虚表之前有 call        → 基类构造
  ② 虚表被写入两次           → 有继承（先基类表后派生表）
  ③ this 有偏移调整          → 多重/虚继承（单继承无此特征）
     add ecx, 8 / sub ecx, 10h 再 jmp = adjustor thunk
  ④ 虚表[-1] 有指针被引用    → RTTI
  ⑤ 类无虚函数则 ①②④ 全灭  → 只能靠构造链 + 成员偏移聚类硬啃

RTTI 辅助识别


  位置：虚表[-1] → Complete Object Locator
       → Class Hierarchy Descriptor
       → Base Class Array（基类描述符数组）
       → 各基类的类型名 + 在对象中的偏移量

  局限：
    - 只对多态类生成（类里必须有虚函数）
    - /GR- 可关，发布版可能没有
    - 用了 dynamic_cast/typeid 会强制开启
