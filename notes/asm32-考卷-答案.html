32位汇编综合考卷 - 参考答案

一、选择题答案

1. B - __stdcall（Win32 API标准约定，被调用者清栈） 2. A - 调用者（__cdecl最大特点是调用者清栈，支持可变参数） 3. B - ECX, EDX（__fastcall前两个参数走寄存器，其余压栈） 4. B - 线程环境块（TEB，FS:[0]是SEH链头，FS:[30h]是PEB） 5. B - PUSH EBP（保存调用方的帧基址是第一步） 6. B - 字符串函数遇到NULL会截断（strcpy等C字符串函数以\0结尾，遇到NULL停止复制） 7. C - PAGE_EXECUTE_READWRITE（Shellcode需要执行权限） 8. A - BeingDebugged（PEB+0x02，被调试时值为1） 9. B - 替换指令首字节为0xCC（INT 3，软中断断点） 10. B - 4个（DR0~DR3，x86架构限制） 11. A - FS:[0]（SEH链表头指针在TEB偏移0处） 12. B - 5字节（E9 + 4字节rel32偏移） 13. B - 目标地址 - (JMP指令地址 + 5)（rel32是相对于下一条指令的偏移） 14. B - 链接时找不到符号（C++的name mangling导致符号名不匹配） 15. A - 不生成函数序言和尾声代码（naked函数体完全由程序员控制）

三、判断题答案

1. √ - 寄存器传参避免了内存访问，减少栈操作

2. × - EBX是被调用者保存寄存器（Callee-Saved），需要在函数内保存恢复

3. √ - Shellcode注入到任意地址，不能依赖硬编码的绝对地址

4. √ - VirtualAlloc在系统级分配，VirtualFree释放；HeapAlloc/HeapFree是堆管理

5. √ - INT 3改写代码段，可通过CRC校验、内存扫描等方式检测

6. √ - 硬件断点支持读、写、执行断点，软件断点只能断执行

7. √ - SEH是链表结构，新注册的挂在链头，异常时从链头开始遍历

8. √ - Trampoline包含代码（原始指令+跳转），必须有执行权限

9. √ - C语言没有name mangling，extern "C"是C++用来禁用名称修饰

10. × - MSVC 64位不支持内联汇编，需要单独.asm文件或使用intrinsic

四、简答题答案

1. __stdcall和__cdecl的区别

主要区别：

| 对比项 | __stdcall | __cdecl | |--------|-----------|---------| | 清栈方 | 被调用者 | 调用者 | | ret形式 | ret N（N=参数字节数） | ret | | 可变参数 | 不支持 | 支持 | | 代码体积 | 小（清栈代码只在被调用者一处） | 大（每个调用点都清栈） |

为什么可变参数只能用__cdecl：

可变参数函数（如printf(fmt, ...)）在编译时不知道参数个数，被调用者无法确定清栈字节数（ret N中的N无法确定）。只有调用者知道实际传了几个参数，所以必须由调用者清栈。

示例：


printf("%d %s", 123, "hello");  // 调用者知道传了3个参数（fmt + 2个可变参数）
// 调用者生成：call printf; add esp, 12（清理3个DWORD）

2. 通过PEB获取kernel32.dll基址

完整路径：


FS:[30h] → PEB → PEB_LDR_DATA (偏移+0x0C)
         → InInitializationOrderModuleList
         → 第1个模块（ntdll.dll）
         → 第2个模块（kernel32.dll）
         → DllBase字段 → kernel32基址

为什么不能硬编码：

1. ASLR（地址空间布局随机化）：Windows Vista+启用ASLR后，kernel32每次加载到的地址都不同 2. 不同系统版本：XP/Win7/Win10的kernel32基址各不相同 3. 32位/64位差异：同一系统下32位和64位进程的地址空间完全独立

硬编码地址只能在特定环境工作，Shellcode需要通用性，必须动态获取。

3. 软件断点和硬件断点对比

软件断点（INT 3）：

  • 原理：替换目标地址首字节为0xCC（INT 3指令），触发异常时调试器接管，恢复原字节，单步执行，再写回0xCC
  • 优点：数量无限制，实现简单
  • 缺点：修改代码段内存，可被CRC校验、内存扫描检测；不能断ROM/只读内存

硬件断点（DR0~DR7）：

  • 原理：在DR0~DR3中写入地址，DR7配置触发条件（执行/读/写），CPU硬件监控，触发时产生调试异常
  • 优点：不修改内存，无法被代码检测；支持数据断点（内存读写断点）
  • 缺点：数量限制（最多4个）；可被反调试代码读取DR寄存器检测

选择建议：

  • 普通调试用软件断点（方便快捷）
  • 反调试保护强的程序用硬件断点
  • 监控数据变化必须用硬件断点

4. Inline Hook为什么需要trampoline

问题分析：

Hook后的执行流：


调用者 → [MessageBoxA入口被改为JMP hook_func]
      → hook_func执行
      → 需要调用原始MessageBoxA？

直接调用的问题：

如果在hook_func中直接call MessageBoxA，会跳到MessageBoxA入口，而入口已经被改成JMP hook_func，形成无限递归：


hook_func → call MessageBoxA
          → JMP hook_func
          → call MessageBoxA
          → JMP hook_func
          → （死循环）

Trampoline的作用：

1. 保存原始指令：将MessageBoxA入口被覆盖的5字节（或更多）复制到trampoline 2. 跳回后续代码：在trampoline末尾跳转到MessageBoxA+5，绕过hook入口 3. 调用trampoline：hook_func调用trampoline地址，等同于调用原始MessageBoxA

结构：


; MessageBoxA原始入口（已被hook）：
76A50000: E9 FB 0F BA 89    jmp 00401000  ; 跳到hook_func

; Trampoline：
00402000: 8B FF             mov edi, edi   ; 原始指令1
00402002: 55                push ebp       ; 原始指令2
00402003: 8B EC             mov ebp, esp   ; 原始指令3
00402005: E9 F6 EF 65 76    jmp 76A50005   ; 跳回MessageBoxA+5

五、代码阅读题答案

1. 函数分析

  • 调用约定：__stdcall（ret 8，被调用者清栈8字节=2个参数）
  • 参数个数：2个（[ebp+8]和[ebp+0Ch]）
  • 局部变量空间：16字节（sub esp, 10h）
  • 函数功能：计算两个参数的和，存入局部变量[ebp-4]，返回该和值

等价C代码：


int __stdcall Add(int a, int b) {
    int result = a + b;
    return result;
}

2. Shellcode分析

  • 目的：实现位置无关代码（PIC），动态获取当前执行地址（EIP）
  • 为什么不能直接mov：Shellcode注入到任意地址，编译时的offset data是相对于原始编译基址的，注入后失效。必须通过call/pop技巧获取运行时EIP
  • EBX最终指向：data标签的运行时地址

原理：


call get_eip          ; 压入返回地址（下一条指令地址）到栈
get_eip:
pop ebx               ; EBX = 当前get_eip标签地址
add ebx, offset_to_data  ; EBX += 相对偏移 → data的运行时地址

这是经典的GetPC（Program Counter）技巧，32位Shellcode必备。

六、编程题答案


.386
.model flat, stdcall
option casemap:none

.code

MaxOfThree proc a:DWORD, b:DWORD, c:DWORD
    push ebp
    mov ebp, esp

    mov eax, a              ; EAX = a
    cmp eax, b              ; 比较 a 和 b
    jge @check_c            ; 如果 a >= b，检查c
    mov eax, b              ; 否则 EAX = b

@check_c:
    cmp eax, c              ; 比较当前最大值和c
    jge @done               ; 如果 >= c，已经是最大值
    mov eax, c              ; 否则 EAX = c

@done:
    pop ebp
    ret 12                  ; stdcall清栈：3个参数 × 4字节 = 12

MaxOfThree endp

end

评分标准：

  • 建立栈帧（push ebp; mov ebp, esp）：2分
  • 比较逻辑正确（找出最大值）：5分
  • ret 12（stdcall清理12字节）：2分
  • 返回值在EAX：1分

优化版本（使用CMOV指令，P6+）：


MaxOfThree proc a:DWORD, b:DWORD, c:DWORD
    mov eax, a
    mov edx, b
    cmp eax, edx
    cmovl eax, edx          ; 如果 a < b，EAX = b
    mov edx, c
    cmp eax, edx
    cmovl eax, edx          ; 如果 max(a,b) < c，EAX = c
    ret 12
MaxOfThree endp

七、综合分析题答案

1. 计算跳转指令机器码（5分中的2分）

计算过程：


目标地址（hook函数）：0x00401000
JMP指令地址：0x76A50000
rel32 = 目标地址 - (JMP地址 + 5)
      = 0x00401000 - 0x76A50005
      = 0x899B0FFB  （补码表示的负数）

机器码（小端序）：


E9 FB 0F 9B 89
  • E9：JMP rel32操作码
  • FB 0F 9B 89：0x899B0FFB的小端序表示

2. Trampoline内容（2分）


; Trampoline @ 0x00402000
00402000: 8B FF             mov edi, edi   ; 原始指令1（2字节）
00402002: 55                push ebp       ; 原始指令2（1字节）
00402003: 8B EC             mov ebp, esp   ; 原始指令3（2字节）
00402005: E9 F6 EF 65 76    jmp 0x76A50005 ; 跳回MessageBoxA+5

要点：

  • 复制被覆盖的5字节原始指令
  • 末尾跳转回MessageBoxA+5（绕过hook入口）
  • 计算：0x76A50005 - (0x00402005 + 5) = 0x7664EFF6

3. MOV EAX, 1的hook问题（2分）

答案：没有问题

B8 01 00 00 00是一条完整的5字节指令，指令边界对齐，直接覆盖不会切断指令。

但需注意：

  • 这条指令被完全覆盖，trampoline中需要包含这5字节
  • 如果后续指令有跳转到MessageBoxA+1~+4的情况（非常罕见），会跳入JMP指令中间，导致CPU解码错误

4. 包含RET的hook问题（2分）

答案：不能安全hook


8B 44 24 04    mov eax, [esp+4]  ; 4字节
C3             ret                ; 1字节

问题：

  • 前5字节包含一条完整的RET指令
  • 如果覆盖这5字节，RET被破坏，函数无法正常返回
  • Trampoline执行mov eax, [esp+4]后遇到被破坏的RET，会继续执行后续代码（本应返回）

解决方案：

  • 识别到短函数（含RET），选择hook更靠后的位置
  • 或者在trampoline中手动重建返回逻辑（复杂）

5. 多线程Hook安全性（2分）

问题：原子性缺失

写入5字节不是原子操作：


时刻T1：写入 E9（JMP操作码）
时刻T2：线程B执行到此，读到 E9 + 旧的4字节偏移 → 跳到错误地址 → 崩溃
时刻T3：写入完整的rel32偏移

解决方案：

1. 暂停所有线程：


   SuspendThread(hThread);  // 暂停其他线程
   WriteProcessMemory(...); // 写入hook
   ResumeThread(hThread);   // 恢复线程

2. 原子替换（热补丁技术）：

  • 先在目标函数前插入2字节短跳转槽位：EB F9（jmp $-5）
  • 在函数-5位置写入长跳转：E9 xx xx xx xx
  • 最后原子修改函数入口2字节为EB F9（跳到-5处的长跳转）
  • 2字节写入在x86上是原子的（对齐的WORD写入）

3. 硬件断点替代（临时hook）：

  • 设置DR0为目标函数地址，DR7配置执行断点
  • 异常处理器中劫持执行流
  • 不修改代码段，无原子性问题
