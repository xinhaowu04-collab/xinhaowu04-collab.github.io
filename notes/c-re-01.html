手动寻找 main 的三种课堂方法

C 逆向

手动寻找 main 的三种课堂方法

方法一：从上往下找

  • 从 CRT 入口或启动函数开始向下分析
  • 寻找准备三个参数后调用某个函数的位置
  • 重点关注 argc、argv、envp 的来源
  • 不能只按 push 数量判断

方法二：从 exit 向上找

  • 找 exit 或相关退出函数
  • 查看交叉引用
  • 向上追踪传给退出函数的返回值
  • 常见逻辑：


exit(main(argc, argv, envp));
  • 返回值产生位置附近可能出现 main 调用
  • 中间可能存在 CRT 包装、异常处理或清理函数

方法三：从 argc 相关运行库函数反查

  • 在导入表或函数列表中查找运行库相关名称
  • 可能出现：__getmainargs、__p___argc 等
  • 对这些函数查看交叉引用
  • 先定位 CRT 启动函数，再寻找对 main 的调用
  • 准确说法：不是“导入表中有 argc”，而是有获取/准备 argc 的运行库函数
  • 不同 CRT 版本函数名可能不同

main 定位的验证标准

  • 调用参数是否对应 argc、argv、envp
  • 被调用函数的返回值是否进入退出流程
  • 是否处于 CRT 启动函数的合理控制流位置
  • 是否有其他包装函数介入
  • 伪代码和汇编是否互相印证

库函数识别

动态库函数（DLL 导入）

  • 函数代码位于外部 DLL
  • PE 导入表中保存导入信息
  • 可能有函数名、序号或 IAT 项
  • IDA 通常可以识别常见导入函数
  • 常见例子：printf、MessageBoxA
  • 按序号导入、动态解析或 GetProcAddress 可能没有直接函数名
  • 导入表有符号不代表所有调用都能自动识别

静态库函数

  • .lib 中的目标代码在链接时复制到 EXE
  • 函数本身通常不会出现在 DLL 导入表
  • 整个程序仍然可能有其他 DLL 导入
  • 函数可能被链接器或编译器内联，导致原函数边界消失
  • /GL、/LTCG 会增加跨文件优化和内联机会
  • 静态库函数可能显示为 sub_xxxxx

iob、标准流与 CRT

标准流下标

传统或现代 MSVC CRT 中可能看到：



__iob_func(0)       // 旧式 CRT 相关形式

__acrt_iob_func(0)  // 较新的 UCRT 形式
  • 下标 0：stdin，标准输入
  • 下标 1：stdout，标准输出
  • 下标 2：stderr，标准错误

不能直接这样判断

  • 下标 0 不等于一定是 scanf
  • 下标 1 不等于一定是 printf
  • 还要看后续对 FILE * 的操作、格式字符串和参数

可能的语义

  • stdin：scanf、fscanf、fgets、fread
  • stdout：printf、fprintf、fputs、fwrite
  • stderr：错误输出、日志输出
  • 只能根据完整调用链重命名，不能只看 iob 下标

版本差异

  • 旧 CRT 可能出现 __iob_func
  • 新 CRT/UCRT 可能出现 __acrt_iob_func

FLIRT、.pat 与 .sig

  • FLIRT 用于识别已知库函数
  • 重点场景：静态链接进程序的库函数
  • .pat：函数特征提取阶段的模式文件
  • .sig：供 IDA 加载使用的签名文件
  • 常见流程：


库目标文件/样本

→ 提取函数特征

→ 生成 .pat

→ 使用 sigmake 等工具转换

→ 得到 .sig

→ 在 IDA 中加载
  • .sig 用于库函数识别，不等于表达式优化指令的固定签名

加法优化特征

x + 1

  • 可能使用：add、inc、lea
  • 可能形式：


add eax, 1

inc eax

lea eax, [eax+1]

x + 2、x + 100

  • 常见：add reg, imm
  • 也可能用 lea
  • 不能因为出现立即数就认定没有优化

x + x

  • 等价于 x * 2
  • 可能使用：add x,x、shl x,1、lea x,[x+x]

减法优化特征

x - 1

  • 可能使用：sub、dec、lea

x - x

  • 结果通常直接变成零
  • 可能使用：xor reg,reg、sub reg,reg、mov reg,0
  • 如果涉及 volatile、内存访问或副作用，不能机械化简

标志位注意事项

  • inc 不修改 CF
  • dec 不修改 CF
  • add、sub 会修改 CF
  • lea 不修改算术标志位
  • 如果后面使用 adc、sbb、jb 等，必须结合标志位分析

乘法优化特征

乘以 2 的幂



x * 2^k = x << k
  • x * 2：可能是 add、shl 1、lea
  • x * 4：可能是 shl 2、lea
  • x * 8：可能是 shl 3、lea
  • 这里的 k 是移位位数，不是被乘数本身

x * 6



x * 6 = x * 3 * 2

x * 3 = x + x * 2
  • 可能是 lea 先算 3x，再加倍
  • 也可能直接使用 imul 6

x * 63



x * 63 = x * 64 - x

       = (x << 6) - x
  • 可能出现 shl 加 sub
  • 分析时要确认原始 x 是否被保留

x * 53

可进行多种代数拆分：



53 = 32 + 16 + 4 + 1

53 = 3 * 9 * 2 - 1
  • 编译器不一定按课堂推导的拆分生成
  • 可能使用多条 lea、shl、add、sub
  • 也可能直接使用 imul 53

x * x

  • 两个操作数都是运行时变量
  • 通常使用 imul
  • 不能按乘以常量的方式直接换成固定移位

LEA 的整数运算

  • lea 不一定是取地址
  • 常见比例因子：1、2、4、8
  • 例如：


lea eax, [ecx+ecx*4]
  • 语义：eax = ecx * 5
  • 判断依据：操作数、数据流和后续用途，不是指令名字本身

常量折叠与 argc 实验

常量表达式



printf("%d\n", 1 + 2);

printf("%d\n", 3 * 6);
  • 1 + 2 可能编译期直接变成 3
  • 3 * 6 可能编译期直接变成 18
  • printf 调用本身仍可能保留，因为输出有副作用

argc 表达式



argc + 1

argc + 2

argc + 100

argc + argc

argc - 1

argc - 2

argc - 100

argc - argc

argc * 4

argc * 6

argc * 63

argc * 53

argc * argc
  • argc 是运行时参数，不能像常量 1 + 2 一样直接折叠成固定结果
  • argc + argc 可能优化为乘以 2 的形态
  • argc - argc 通常可直接化为零
  • 乘以常量可能使用移位、lea、加减或 imul
  • 变量乘变量通常保留 imul
  • 源码中的格式字符串标签要和实际表达式一致
