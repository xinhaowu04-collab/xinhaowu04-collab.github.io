指令集速查

32 位汇编

指令集速查

x86 指令集是 Intel 兼容处理器使用的 CISC（复杂指令集计算机）指令体系。每条指令对应 CPU 执行的一个基本操作，包括数据搬运、算术运算、逻辑运算、控制流改变等。x86 指令长度不固定（1~15 字节），采用变长编码，历史上兼容到 8086，每条指令通过 opcode + ModRM + SIB + 偏移量 + 立即数的格式编码。

指令分类概览

| 类别 | 代表指令 | 功能 | |---|---|---| | 数据传送 | mov, push, pop, lea | 在寄存器、内存、立即数之间搬运数据 | | 算术运算 | add, sub, mul, div | 整数加减乘除 | | 位运算 | and, or, xor, shl, shr | 按位逻辑与移位 | | 比较与跳转 | cmp, test, jcc | 条件判断与分支 | | 函数调用 | call, ret | 子程序调用与返回 |

操作数类型

x86 指令的操作数分为三种：

  • 立即数（Immediate）：常量值直接编码在指令字节中，如 42、0FFFFh
  • 寄存器（Register）：CPU 内部命名存储单元，如 eax、ecx
  • 内存（Memory）：通过地址引用 RAM，如 [ebx]、wc

注意：一条指令最多可有两个操作数，且最多只有一个操作数可以是内存（mov mem, mem 不合法）。这是 x86 指令编码格式（ModRM 字节）的硬约束。

内存寻址方式


[立即地址]        ; 直接寻址:     mov eax, [00401234h]
[寄存器]           ; 寄存器间接:   mov eax, [ebx]
[基址 + 偏移]      ; 基址寻址:     mov eax, [ebx + 8]
[基址 + 变址]      ; 基址变址:     mov eax, [ebx + esi]
[基址 + 变址*n]    ; 比例变址:     mov eax, [ebx + esi*4]
[基址 + 变址*n + 偏移]  ; 最完整形式

完整形式为 [base + index*scale + disp]，其中 scale 只能是 1、2、4、8。这个能力由 SIB（Scale-Index-Base）字节提供，是 x86 指令编码中特有的复杂寻址方式。

指令的执行过程

所有 x86 指令都遵循"取指—译码—执行—写回"这四步周期，每条指令在每个阶段的具体操作不同：

1. 取指：CPU 从 eip 指向的内存地址读取指令字节流 2. 译码：CPU 解析 opcode 和 ModRM 字节，确定指令的操作码、操作数类型和位置 3. 取操作数：从寄存器文件、内存或指令本身提取源数据 4. 执行：ALU 执行运算或地址计算单元计算有效地址（EA） 5. 写回：将结果写入目标寄存器或内存

mov 为什么是"拷贝"不是"移动"

x86 的寄存器文件是独立存储单元，没有"移动后源清零"的硬件语义。mov eax, ebx 在 CPU 内部等价于：


寄存器读取端口 → 读取 ebx 的值
寄存器写入端口 → 将值写入 eax

ebx 的存储单元不会被修改。名为 mov 是历史惯例，实际语义始终是拷贝。

为什么 xor eax, eax 比 mov eax, 0 更快

这是逆向分析中常见的编译器优化现象，原因涉及多层微架构：

1. opcode 更短：xor eax, eax 编码为 2 字节（31 C0），而 mov eax, 0 编码为 5 字节（B8 00 00 00 00），节省指令缓存（i-cache）空间 2. 消除错误依赖：xor eax, eax 被 CPU 识别为等零惯用法（Zeroing Idiom），现代 CPU 会将 eax 标记为常量 0，不等待上一指令对 eax 的计算结果，打破数据流中的数据依赖链 3. 微架构快速路径：Intel Sandy Bridge 之后的微架构对 xor same,same 有专门的等零执行端口，无需占用 ALU 算术单元

cmp / test 的标志位机制

cmp 和 test 的本质是"只设标志，不存结果"：

  • cmp a, b 内部执行 a - b，ALU 计算出差值，但差值被丢弃，只更新 EFLAGS 的 ZF、SF、CF、OF
  • test a, b 内部执行 a & b，也同样丢弃结果只更新标志

lea 不访问内存的设计动机

lea（Load Effective Address）最初是为高级语言指针运算设计的。它让编译器用一条指令完成数组下标计算：


lea eax, [ebx + ecx*4 + 8]

这条指令完全在地址生成单元（AGU）中完成，不触发内存总线事务，也不读取 TLB/缓存，因此比等效的 mov + shl + add 序列更快，且不改变任何 EFLAGS 标志位，这是它相比 add/shl 组合的额外优势。

栈操作的内存模型

push 和 pop 基于栈的向下增长模型：


push eax 的完整操作：
  sub esp, 4        ; esp 减 4，栈顶下移一个槽位
  mov [esp], eax    ; 将 eax 写入新栈顶

pop eax 的完整操作：
  mov eax, [esp]    ; 从栈顶读出到 eax
  add esp, 4        ; esp 加 4，栈顶上移释放槽位

惯用模式

模式一：xor eax, eax 清零（编译器首选写法）

字面语义是"异或"，但实际用途 99% 是清零。所有现代编译器生成清零代码都用 xor reg, reg 而非 mov reg, 0。


xor eax, eax    ; eax = 0，编码 2 字节（31 C0）
; 而非
mov eax, 0       ; eax = 0，编码 5 字节（B8 00 00 00 00）

注意：反汇编里看到 xor eax, eax / xor ecx, ecx，第一反应是"清零"而非"异或运算"。同理 sub eax, eax 也是清零惯用法。看到 mov reg, 0 反而可能是手写汇编或未优化代码。

模式二：test eax, eax 判零（cmp eax, 0 的高效替代）

字面语义是"与运算"，但实际用途是判断寄存器是否为零。编译器判零几乎总是用 test 而非 cmp。


test eax, eax    ; 自己 AND 自己，结果丢弃只设 ZF。2 字节
jz   is_zero     ; ZF=1 则 eax==0
; 而非
cmp  eax, 0      ; 3-5 字节，功能等价但更慢

注意：test reg, reg 紧跟 jz/jnz 是"判零跳转"的标准信号，几乎从不表示真正的按位与运算。看到 cmp reg, 0 反而要警惕——可能是手写代码或特殊场景。

模式三：lea 做地址运算（编译器优化利器）

字面语义是"加载有效地址"，但实际高频用途是借寻址电路做三操作数加法 + 移位，一条指令替代多条，且不改变标志位。


; 编译器常用：一条 lea 完成 ebx + ecx*4 + 8
lea eax, [ebx + ecx*4 + 8]
; 等价但更差的多条写法：
; mov eax, ecx / shl eax, 2 / add eax, ebx / add eax, 8

注意：看到 lea 带 [base + index*scale + disp] 复杂寻址，第一反应是"编译器在做指针/下标运算"，而非真的要读内存。区分：lea eax, [ebx] 取地址，mov eax, [ebx] 取值。

模式四：cmp + 条件跳转 jcc 配对（比较-分支标准模式）

cmp 单独出现没有意义，必须紧跟一个条件跳转。这是"比较并分支"的固定搭配，编译器生成的几乎所有 if/while 都基于此。


cmp eax, 100
je  equal        ; ==
jg  greater      ; 有符号 >
ja  above        ; 无符号 >（指针/句柄比较必用这个）

注意：cmp + jcc 是 if/switch/while 的信号。关键区分：jg/jl/jge/jle（g/l）是有符号比较，ja/jb/jae/jbe（a/b）是无符号比较。比较指针/句柄/内存大小时编译器必用 ja/jb，比较有符号整数用 jg/jl。

模式五：mov mem, mem 禁忌（必须寄存器中转）

x86 硬件不支持单条指令做内存到内存的搬运，这是 ModRM 编码的硬约束。


; ❌ 非法
mov [dest], [src]
; ✅ 寄存器中转
mov eax, [src]
mov [dest], eax
; ✅ 或栈中转
push [src]
pop  [dest]

注意：反汇编里绝不会出现两个内存操作数的指令——如果逻辑上需要内存到内存搬运，编译器必然插入一条寄存器中转（常见 eax）。看到 mov eax, [src]; mov [dest], eax 这种成对模式，说明源码里有一次内存间赋值。

数据传送指令

| 指令 | 作用 | 例子 | |---|---|---| | mov dest, src | 拷贝（源不变） | mov eax, 42 | | push src | 压栈 | push 0 | | pop dest | 弹栈 | pop eax | | lea dest, src | 取地址（不读内存） | lea eax, wc | | movzx dest, src | 零扩展拷贝（高位填 0） | movzx edx, ax | | movsx dest, src | 符号扩展拷贝（高位填符号位） | movsx ecx, al | | xchg a, b | 交换两个值 | xchg eax, ebx |

mov 合法组合


✅ mov 寄存器, 立即数
✅ mov 寄存器, 寄存器
✅ mov 寄存器, 内存
✅ mov 内存,   立即数
✅ mov 内存,   寄存器
❌ mov 内存,   内存      --> CPU 不支持，必须中转
❌ mov 立即数, 任何东西

mov 是拷贝不是移动，源操作数的值不变。名字叫 mov 是历史遗留，记住"它不破坏源"就行。

内存到内存的两种解决办法


; 方法1：寄存器中转（推荐，不修改 esp）
mov eax, hInst
mov wc.hInstance, eax

; 方法2：栈中转（省一行，但会改 esp）
push hInst
pop wc.hInstance

方法 2 虽然代码更短，但会临时修改 esp，在多线程或中断敏感的代码中需要谨慎。

movzx / movsx 使用规则

  • 无符号数用 movzx（零扩展，高位填 0）
  • 有符号数用 movsx（符号扩展，高位填符号位）

; al = 0xFF
movzx ecx, al    ; ecx = 0x000000FF（255，无符号解释）
movsx edx, al    ; edx = 0xFFFFFFFF（-1，有符号解释）

选择依据取决于你对数据的解释方式：如果 0xFF 是 RGB 颜色分量（无符号），用 movzx；如果是温度传感器的 -1 度（有符号），用 movsx。

lea vs mov


lea eax, wc          ; eax = wc 的地址（不读内存）
mov eax, wc          ; eax = wc 里的值（读内存）

lea 还能做地址运算，一条指令替代多条：


; 一条 lea（编译器常用此技巧优化）
lea eax, [ebx + ecx*4 + 8]

; 等价的多条指令（更长、更慢、修改标志位）
mov eax, ecx
shl eax, 2
add eax, ebx
add eax, 8

lea 不访问内存也不改变标志位，这是它相比 add/shl 组合的额外优势。

算术运算指令

| 指令 | 作用 | |---|---| | add dest, src | dest = dest + src | | sub dest, src | dest = dest - src | | inc dest | dest++ | | dec dest | dest-- | | imul eax, src | 有符号乘，结果在 eax | | mul ecx | 无符号乘，64 位结果在 edx:eax | | div ecx | 无符号除，商在 eax，余数在 edx；调用前必须 xor edx, edx |

乘法指令的细节

mul 是无符号乘法，结果宽度自动扩展为操作数的两倍，存入固定的寄存器对：

  • mul bl：ax = al * bl（8 位乘）
  • mul bx：dx:ax = ax * bx（16 位乘）
  • mul ecx：edx:eax = eax * ecx（32 位乘）

imul 的有符号双操作数形式（imul dest, src）只保留结果的低半部分到 dest，不扩展，但三操作数形式（imul dest, src1, src2）在现代代码中更为常用。

除法指令的陷阱

div 将 edx:eax 拼接为 64 位数作为被除数。如果忘记在调用前清零 edx，会得到一个随机的高 32 位值，导致商超出 32 位范围，触发 #DE（Divide Error）异常，程序崩溃：


; 正确的做法
xor edx, edx    ; 清零高 32 位
div ecx         ; eax = edx:eax / ecx, edx = edx:eax % ecx

; 错误的做法
div ecx         ; edx 是上一指令的残值 --> 结果不可预测，可能崩溃

对于有符号除法 idiv，需要用 cdq 指令将 eax 的符号位扩展到 edx：


; 有符号除法
cdq              ; edx = eax 的符号扩展
idiv ecx         ; 有符号除

位运算指令

| 指令 | C 等价 | 规则 | |---|---|---| | and dest, src | a & b | 都 1 才 1 | | or dest, src | a \| b | 有 1 就 1 | | xor dest, src | a ^ b | 不同才 1 | | not dest | ~a | 0 变 1，1 变 0 | | shl dest, n | a << n | 左移，右边补 0，等价于 × 2ⁿ | | shr dest, n | a >> n | 逻辑右移，左边补 0，等价于 ÷ 2ⁿ（无符号） | | sar dest, n | -- | 算术右移，左边补符号位，等价于 ÷ 2ⁿ（有符号） |

常用技巧


xor eax, eax          ; 清零，比 mov eax, 0 更短更快
xor eax, 1            ; 翻转最低位（toggle bit 0）
and eax, 0FFFFh       ; 取低 16 位，高位清零
shr eax, 16           ; 取高 16 位（右移到低位）

; xor 交换两个值（不用临时变量）
xor eax, ebx
xor ebx, eax
xor eax, ebx

注意：虽然 xor swap 节省了栈空间，但在现代 CPU 上未必比 push/pop 或临时寄存器交换快。xor 的三条指令之间存在数据依赖链（每条的结果是下一条的输入），无法超标量并行执行。而 xchg 或 push/pop 在寄存器充足的现代架构上往往更快。

移位指令的转向控制

移位计数 n 可以是立即数（1~31）或 cl 寄存器：


shr eax, 1       ; 右移 1 位
shr eax, cl      ; 右移 cl 指定的位数（动态移位）

shl 和 shr 在移出最后一位时会更新 CF 标志，可以用 jc / jnc 检测被移出的位。

比较与跳转指令

cmp 做减法但不存结果，只设标志位（等同于只看不摸的 sub）。test 做 AND 但不存结果，只设标志位（等同于只看不摸的 and）。


; 检查 eax 是否为 0（最常用写法）
test eax, eax
jz done

; 比较大小
cmp eax, 5
je  equal
jne not_equal
jg  greater      ; 有符号大于
jl  less         ; 有符号小于
ja  above        ; 无符号大于
jb  below        ; 无符号小于

EFLAGS 标志位

| 标志 | 全称 | 置 1 条件 | |---|---|---| | ZF | Zero Flag | 结果为 0 | | SF | Sign Flag | 结果为负（最高位 = 1） | | CF | Carry Flag | 无符号运算溢出/借位 | | OF | Overflow Flag | 有符号运算溢出 |

跳转指令速查

| 指令 | 条件 | 适用 | |---|---|---| | je / jz | ZF=1 | == / 为零 | | jne / jnz | ZF=0 | != / 非零 | | jg | ZF=0 且 SF=OF | 有符号 > | | jge | SF=OF | 有符号 >= | | jl | SF != OF | 有符号 < | | jle | ZF=1 或 SF != OF | 有符号 <= | | ja | CF=0 且 ZF=0 | 无符号 > | | jb | CF=1 | 无符号 < | | jae | CF=0 | 无符号 >= | | jbe | CF=1 或 ZF=1 | 无符号 <= | | jmp | 无条件 | -- |

注意：有符号比较用 g/l（Greater/Less），无符号比较用 a/b（Above/Below），混用是常见 bug。必须根据变量的语义选择正确的跳转指令：


; eax = -1 (0xFFFFFFFF)
cmp eax, -1
jg  is_greater   ; 不跳转（有符号: -1 不大于 -1）
ja  is_above     ; 不跳转（无符号: 0xFFFFFFFF 不大于 0xFFFFFFFF）

cmp eax, -2
jg  is_greater   ; 跳转（有符号: -1 > -2）
ja  is_above     ; 跳转（无符号: 0xFFFFFFFF > 0xFFFFFFFE）

test 的隐式操作数

test eax, eax 是将 eax 与自己做 AND，如果 eax 为 0 则 ZF=1，否则 ZF=0。这比 cmp eax, 0 更高效，因为 test 编码只需要 2 字节，而 cmp eax, 0 需要 3~5 字节（取决于 eax 的编码形式）。

函数调用与返回指令

| 指令 | 作用 | |---|---| | call func | 压返回地址 + 跳转（等价于 push eip; jmp func） | | ret | 弹返回地址跳回（pop eip） | | ret N | 弹返回地址 + 清理 N 字节参数（stdcall 使用） |

call func 的完整操作：


push eip       ; 将下一条指令的地址压栈
jmp func       ; 跳转到 func 的起始地址

ret 的完整操作：


pop eip        ; 从栈顶弹出返回地址到 eip

ret N 额外清理栈参数：


pop eip        ; 弹出返回地址
add esp, N     ; 跳过 N 字节参数

调用约定决定了是调用方（cdecl）还是被调用方（stdcall）负责清理参数，这决定了函数结尾是 ret 还是 ret N。

匿名标号

MASM/TASM 提供的语法糖，适用于局部短跳转，避免为每个循环起名：


@@:                ; 定义匿名标号
    ...
    jne @F         ; 跳到前方（Forward）最近的 @@
    ...
    jmp @B         ; 跳到后方（Backward）最近的 @@
@@:
    ; 这里是从前面 @F 跳来的目标
  • @F（Forward）：跳转到下方最近的 @@
  • @B（Backward）：跳转到上方最近的 @@
  • 作用域局限于当前过程（proc/endp 之间），不会与其他过程冲突
