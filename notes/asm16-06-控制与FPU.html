8086 控制指令与 FPU

循环指令

8086 有三条循环指令，全部隐式操作 CX 寄存器。优点是少写代码，但不灵活——定死了用 CX 做计数器，嵌套循环只能用 PUSH CX / POP CX，反而更慢。

LOOP label

每次执行：CX = CX - 1，若 CX ≠ 0 则跳转到 label。


    mov cx, 5
again:
    ; 循环体
    loop again      ; CX: 5→4→3→2→1→0，跳转4次，共执行5次

注意先减再判断：CX=0 时不跳，直接向下执行。

LOOPE / LOOPZ label

两个助记符等价。条件：CX ≠ 0 且 ZF = 1 才跳转。

语义：循环，直到 CX 耗尽或某次比较结果不相等。


    mov cx, 10
scan:
    cmp [si], al    ; 比较当前元素
    inc si
    loope scan      ; CX≠0 且 ZF=1（即还相等）时继续

典型用途：在数组中扫描，找到第一个不等于 AL 的元素时停下。

LOOPNE / LOOPNZ label

条件：CX ≠ 0 且 ZF = 0 才跳转。

语义：循环，直到 CX 耗尽或某次比较结果相等。


    mov cx, 10
find:
    cmp [si], al    ; 比较
    inc si
    loopne find     ; CX≠0 且 ZF=0（即还不等）时继续

典型用途：在数组中搜索，找到第一个等于 AL 的元素时停下。

关键细节

跳转范围是短跳转。label 必须在当前 IP -128 ~ +127 字节以内（从下一条指令的 IP 算起），编码为 8 位有符号偏移。循环体过大时编译器报错，只能手动改用 DEC CX + JNZ。

LOOP 不影响任何标志位。CX 的递减不像 DEC CX 那样会改变 ZF/SF/OF。这是个陷阱——不能在 LOOP 之后用 JZ 判断 CX 是否减到零，因为 ZF 还是上一条指令留下的状态：


sub ax, 1        ; 修改了 ZF
loop label       ; CX--，但不改 ZF
jz somewhere     ; 这里的 ZF 是 sub 留下的，不是 CX 是否为 0

LOOPE/LOOPNE 只读 ZF，不写 ZF。ZF 由循环体内的 CMP/SUB 等指令设置，LOOPE 本身只消费它。

CX=0 进入时的行为：如果进入 LOOP 时 CX 已经是 0，减一变成 0xFFFF（65535），循环会跑 65536 次。经典陷阱，进循环前必须确保 CX > 0。

与 DEC CX + JNZ 的对比


; LOOP 写法
    loop label

; 等价的显式写法
    dec cx
    jnz label

唯一区别：DEC CX 会修改 ZF/SF/OF，LOOP 不会。在循环体内依赖标志位时，这个差异很重要。另外"大于等于"这类条件无法用循环指令表达，不够灵活。

标志位操作指令

8086 有三条专门操作 CF 的指令（CLC/STC/CMC），直接读写进位标志，不涉及任何通用寄存器。LAHF/SAHF/PUSHF/POPF 见 02a-寻址与数据传送。

CLC / STC / CMC


CLC     ; CF = 0，无条件清除进位标志
STC     ; CF = 1，无条件置位进位标志
CMC     ; CF = ~CF，取反

三条指令都是单字节编码，不影响其他标志位（OF、ZF、SF、PF 全部不变），也不读写任何寄存器。

多精度加减法

8086 寄存器只有 16 位，做 32 位甚至更宽的整数运算时，需要手动把低字的进位传给高字。ADC 和 SBB 都依赖 CF，所以在链式运算开始前用 CLC 清零是标准做法：


; 32位加法：DX:AX + BX:CX → DX:AX
CLC
ADD AX, CX      ; 低16位相加，结果的进位存入 CF
ADC DX, BX      ; 高16位相加，CF 作为进位加进来

如果不 CLC，CF 可能是上一条无关指令留下的脏值，高字结果就错了。

移位配合串行传输

RCL 和 RCR 把 CF 纳入移位链，CF 相当于一个额外的第 17 位：


; 把 AX 的最高位"传"给 BX 的最低位
STC             ; 或 CLC，先设定初始 CF
RCL AX, 1      ; AX 左移，最高位出来进 CF
RCR BX, 1      ; BX 右移，CF 进入 BX 最高位

这是实现大于 16 位的移位操作的基础手段。

用 CF 当函数返回值

DOS 功能调用本身就用这个约定——CF=0 表示成功，CF=1 表示失败。自己写子程序时可以沿用：


; 被调用者
my_proc PROC
    ; ... 处理 ...
    ; 成功路径
    CLC
    RETN
    ; 失败路径
error:
    STC
    RETN
my_proc ENDP

; 调用者
CALL my_proc
JC   handle_error   ; CF=1 跳到错误处理
; 正常继续...

比用 AX 存错误码再比较节省一条 CMP，跳转也更直接。

CMC 的用途

相对少见，主要出现在需要"反转成功失败状态"的场合：


CALL some_proc      ; 约定 CF=1 成功，CF=0 失败（非标准）
CMC                 ; 翻转，变成标准的 CF=0 成功
JC   error

或者在位操作中，需要对 CF 取反再送入下一次 RCL/RCR 时。

其他控制指令

HLT — 停机


HLT     ; 处理器停机，等待中断唤醒

单字节指令，执行后 CPU 停止取指执行，进入停机状态。不是死循环，是真正的硬件级挂起。

执行后发生什么：CPU 停在 HLT 的下一条指令地址上（IP 已指向 HLT 之后），等待三种信号之一唤醒：


NMI（不可屏蔽中断）  → 无条件唤醒
INTR（可屏蔽中断）   → IF=1 时唤醒，IF=0 时继续睡
RESET 信号           → 复位，重新启动

唤醒后处理完中断，从 HLT 的下一条指令继续执行，不是重新执行 HLT。

权限问题：8086 没有保护模式，HLT 谁都能用。x86 保护模式（286 以后）HLT 变成特权指令，用户态执行直接触发 #GP 异常，现代 Windows/Linux 下用户程序执行 HLT 会被操作系统杀掉。

实际用途：

OS 的 idle 循环——没有任务可调度时不能让 CPU 空转（白白耗电发热）：


idle:
    STI     ; 确保中断开着，否则永远醒不来
    HLT     ; 睡，等中断
    JMP idle ; 中断处理完回来，再睡

时钟中断（IRQ0，18.2Hz）定期唤醒，调度器检查有没有新任务，有就切换，没有再 HLT。现代 CPU 在 HLT 状态下会降低主频、切断部分电路，这是 CPU 省电的硬件基础。

DOS 程序等待事件：


wait_loop:
    STI
    HLT             ; 等键盘中断
    MOV AH, 01h
    INT 16h
    JZ  wait_loop   ; 没有按键，继续等

异常处理的终点——内核遇到无法恢复的错误时，停机是最安全的选择：


panic:
    CLI     ; 关中断，不再响应任何事件
    HLT     ; 停机
    JMP panic ; 理论上走不到这里，保险起见

Windows 蓝屏、Linux kernel panic 最终都走到类似这段代码。

HLT 和死循环的区别：


; 死循环——CPU 满载
loop:
    JMP loop

; HLT——CPU 挂起，几乎零功耗
    HLT

在固件、bootloader、内核代码里看到 HLT，说明那里是一个预期的停机点，不是 bug。看到死循环才要怀疑是不是出了问题。

NOP — 空操作


NOP     ; 空操作，单字节 90h

CPU 取指、译码，然后什么都不做，继续执行下一条。在 8086 上实际占用 3 个时钟周期，不改变任何寄存器或内存状态。

实际用途：

  • 代码对齐：在跳转目标前插入 NOP，让目标地址对齐到 4/8/16 字节边界，提高指令预取效率
  • 占位：调试时预留空间，后续用其他指令覆盖
  • 反逆向：在代码中插入 NOP 干扰反汇编器的线性扫描

LOCK 前缀


LOCK INC [mem]   ; 原子性地对内存操作数执行 INC

做了什么：执行期间 CPU 拉低 LOCK# 引脚，通知总线上的其他主设备（另一个 CPU、DMA 控制器）：我正在独占内存总线，你们等着。操作完成后释放。目的是保证"读—改—写"三步作为一个不可分割的原子操作完成，中间不被其他设备插入。

8086 的情况：8086 是单核，LOCK 主要针对 DMA 控制器（8237）。DMA 传数据时也在用内存总线，LOCK 能阻止 DMA 在 CPU 读改写的中间插进来抢总线破坏数据。到了多核时代，LOCK 的主要作用变成协调多个 CPU 核心对共享内存的访问——现代 x86 的 LOCK CMPXCHG 是实现所有用户态锁（mutex、spinlock、无锁队列）的底层指令。

注意：LOCK 封锁的是内存总线，不是 I/O 总线。I/O 端口访问的是外设寄存器，不存在多 CPU 同时写同一个端口的竞争场景。LOCK 前缀也不能加在 IN/OUT 前面，加了直接触发无效操作码异常（#UD）。

ESC 指令 — 协处理器通信


ESC opcode, src
; opcode：6位立即数（0~63），传给协处理器的操作码
; src：寄存器或内存操作数

ESC 是 8086 和外部协处理器（主要是 8087 浮点协处理器）之间的通信机制。CPU 自己不执行这条指令的实际运算，只负责把操作数地址和操作码"递出去"。

为什么需要 ESC：8086 本身只有整数运算单元，没有浮点硬件。做浮点运算有两条路：

  • 软件模拟——用整数指令模拟浮点，慢几十倍
  • 硬件协处理器 8087——插在主板上，和 8086 并行工作，速度快百倍以上

8087 不是独立运行的，它监听 8086 的指令总线，等着 8086 发出 ESC 指令，看到了就接管执行，8086 则继续取下一条指令。

执行时发生什么：


8086 取到 ESC 指令
    ↓
计算 src 的有效地址（如果是内存操作数，做一次假读，触发总线周期）
    ↓
8087 监听到 ESC 操作码，从总线上抓走操作数地址
    ↓
8086 继续执行下一条指令
8087 并行执行浮点运算

如果下一条指令需要 8087 的结果，8086 会检查 8087 的 BUSY 引脚，忙就等——这个等待由 WAIT 指令显式插入。

和 8087 指令的关系：实际写代码时不会手写 ESC，汇编器把 8087 的浮点助记符自动编译成对应的 ESC 编码：


; 你写的
FADD ST, ST(1)      ; 8087 浮点加法

; 汇编器生成的机器码本质
ESC 0, ...          ; 对应的 ESC 操作码

没有 8087 时：ESC 指令对 8086 来说就是空操作——CPU 照常取指、可能做一次假内存读，然后继续往下走。程序不会崩溃，但浮点结果不会出现，数据是垃圾。这就是为什么早期软件启动时会检测 8087 是否存在（通过 INT 11h 的位1），有就走硬件浮点路径，没有就走软件模拟库。

现代的命运：ESC 机制在 486 之后彻底消失。486 把浮点单元直接集成进 CPU 芯片，不再需要外部协处理器和 ESC 这套总线通信协议。浮点指令（x87 FPU 指令集）变成 CPU 内部指令直接执行，ESC 这个助记符成为历史。逆向现代二进制完全见不到 ESC，只有分析古老的 DOS 程序或研究 8086/8088 硬件设计时才会遇到。

WAIT 指令 — 等待协处理器


WAIT    ; 也可写作 FWAIT，单字节指令 9Bh

CPU 检测 8087 的 TEST 引脚（连接 8087 的 BUSY 引脚），如果 8087 还在忙，8086 就在原地反复采样等待，直到 8087 完成才继续执行下一条指令。

为什么需要 WAIT：8086 发出 ESC 指令后不等 8087，直接继续取下一条指令，两者并行跑。这带来一个问题——如果下一条指令需要用 8087 的计算结果，结果还没算完怎么办？


FLD  DWORD PTR [bx]   ; ESC：让 8087 加载浮点数（8087 支持 32/64/80 位浮点）
FMUL ST, ST(1)        ; ESC：让 8087 做乘法（8087 开始算）
; 此时 8087 还在算乘法...
WAIT                   ; 8086 在这里等，直到 8087 算完
FSTP DWORD PTR [result] ; ESC：8087 把结果存回内存

没有 WAIT，8086 可能在 8087 还没把结果写回内存时就去读那块内存，拿到旧数据。

汇编器自动插入：实际写 8087 浮点代码不需要手动写 WAIT，汇编器（MASM）会在需要同步的地方自动插入：


; 你写的
FLD  [bx]
FMUL ST, ST(1)
FSTP [result]

; 汇编器实际生成的机器码序列
9B D9 07        ; WAIT + FLD
9B DC C9        ; WAIT + FMUL
9B D9 1F        ; WAIT + FSTP

每条浮点指令前都自动加了 9Bh（WAIT），确保上一条 8087 操作完成再发下一条。

WAIT 和中断的关系：WAIT 等待期间 8086 仍然响应中断。中断来了会暂停等待，处理完再回来继续采样 TEST 引脚。这意味着中断服务程序里如果也用了浮点指令，必须小心保存和恢复 8087 的状态，否则会破坏被打断的浮点运算现场。

现代的情况：486 把浮点单元集成进芯片后，WAIT/FWAIT 语义保留了下来，但作用变了——不再是等外部协处理器，而是等 FPU 内部流水线把之前的浮点指令提交完，确保异常能被正确捕获。现代 x86 里 FWAIT 还能在 IDA 里看到，出现在浮点异常处理相关的代码周围，但已经和 8087 没有任何关系。

FPU 浮点指令

8087 浮点协处理器（FPU）是 8086 的配套芯片，专门执行浮点运算。8086 本身只有整数运算单元，浮点运算通过 ESC 指令机制交给 8087 处理。在 MASM 中，浮点指令用 F 开头的助记符（如 FLD、FADD、FSTP），汇编器自动编译为对应的 ESC 编码。

数据定义

MASM 用 real4 伪指令定义 32 位单精度浮点数（IEEE 754）：


f1 real4 1.0    ; 32位浮点数，值=1.0
f2 real4 2.0    ; 32位浮点数，值=2.0

real4 等价于 dd，但告知汇编器这是浮点而非整数。还有 real8（64 位双精度，等价 dq）和 real10（80 位临时精度，等价 dt）。

浮点栈

8087 使用独立的浮点寄存器栈（ST(0)~ST(7)），不是 8086 的通用寄存器。浮点运算在栈顶进行：


fld f1           ; 将 f1 加载到 ST(0)（压栈）
fadd f2          ; ST(0) = ST(0) + f2
fstp f1          ; 将 ST(0) 存回 f1，并弹出栈顶

完整示例：


; 数据段
f1 real4 1.0
f2 real4 2.0

; 代码段
fld f1           ; ST(0) = 1.0
fadd f2          ; ST(0) = 1.0 + 2.0 = 3.0
fstp f1          ; f1 = 3.0，栈弹出

浮点栈最多 8 层（ST(0)~ST(7)），连续 FLD 超过 8 次不弹出会触发栈溢出异常。

常用 FPU 指令速查

数据传送：

| 指令 | 功能 | 示例 | |------|------|------| | FLD | 加载浮点数到栈顶（压栈） | FLD ST(2) / FLD mem | | FST | 将栈顶存入目标（不弹出） | FST ST(1) / FST mem | | FSTP | 将栈顶存入目标并弹出 | FSTP mem | | FXCH | 交换 ST(0) 和 ST(i) | FXCH ST(2) |

算术运算：

| 指令 | 功能 | 示例 | |------|------|------| | FADD | 加法 | FADD ST, ST(1) / FADD mem | | FSUB | 减法 | FSUB ST, ST(1)（ST=ST-ST(1)） | | FSUBR | 反向减法 | FSUBR ST, ST(1)（ST=ST(1)-ST） | | FMUL | 乘法 | FMUL ST, ST(1) / FMUL mem | | FDIV | 除法 | FDIV ST, ST(1)（ST=ST/ST(1)） | | FDIVR | 反向除法 | FDIVR ST, ST(1)（ST=ST(1)/ST） | | FCHS | 改变符号（取反） | FCHS | | FABS | 取绝对值 | FABS | | FSQRT | 开平方 | FSQRT | | FRNDINT | 取整（按当前舍入模式） | FRNDINT |

比较指令：

| 指令 | 功能 | 说明 | |------|------|------| | FCOM | 比较 ST(0) 和 ST(i)/mem | 结果反映在 FPU 状态字（C0/C2/C3） | | FCOMP | 比较并弹出 | 比 FCOM 多一次弹出 | | FCOMPP | 比较并弹出两次 | 弹出两个操作数 | | FTST | ST(0) 与 0 比较 | 等价于 FCOM 与 0 | | FXAM | 检查 ST(0) 的类型 | 判断是 NaN、无穷大、零、非规格化等 |

比较结果的读取——FCOM 不直接设置 CPU 的 FLAGS，而是设置 FPU 状态字中的 C0/C2/C3。需要用 FSTSW 把状态字存到内存，再用 SAHF 转到 FLAGS，才能用条件跳转判断（FCOMIP 是 386+ 的直接设置 EFLAGS 方案）：


; 比较 ST(0) 和 ST(1) 的完整流程
FCOM              ; 比较 ST(0) 和 ST(1)
FSTSW  [mem]      ; 把 FPU 状态字存到内存
MOV    AX, [mem]  ; 读到 AX
SAHF              ; 转到 FLAGS（C0→CF, C2→PF, C3→ZF）
JAE    DONE       ; 现在可以用条件跳转了

常数加载：

| 指令 | 加载的值 | |------|---------| | FLDZ | 0.0 | | FLD1 | 1.0 | | FLDPI | π（圆周率） | | FLDL2T | log₂10 | | FLDL2E | log₂e | | FLDLG2 | log₁₀2 | | FLDLN2 | ln 2 |

控制指令：

| 指令 | 功能 | |------|------| | FINIT | 初始化 FPU（复位所有寄存器、清除异常） | | FCLEX | 清除异常标志 | | FSTSW | 将 FPU 状态字存到内存 | | FLDCW | 加载 FPU 控制字（设置精度、舍入模式等） | | FWAIT | 等待 FPU 完成（等价于 WAIT） | | FNOP | FPU 空操作 |
