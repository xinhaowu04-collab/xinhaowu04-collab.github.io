可选头与节表

PE 结构

可选头与节表

ImageBase 是 PE 模块的首选加载基址，即程序希望映像第一个字节落在哪个虚拟地址。它不是某个节的地址，也不等于所有情况下的实际加载地址。PE 中大量位置用 RVA（相对模块开头的偏移）表示，核心关系：


VA = 实际模块基址 + RVA

ImageBase 与可选头

PE32 IMAGE_OPTIONAL_HEADER32 字段：


typedef struct _IMAGE_OPTIONAL_HEADER32 {
    /* Standard fields */
    WORD  Magic;
    /* ... */

    /* Windows-specific fields */
    DWORD BaseOfCode;
    DWORD BaseOfData;
    DWORD ImageBase;
    DWORD SectionAlignment;
    DWORD FileAlignment;
    WORD  MajorOperatingSystemVersion;
    WORD  MinorOperatingSystemVersion;
    WORD  MajorImageVersion;
    WORD  MinorImageVersion;
    WORD  MajorSubsystemVersion;
    WORD  MinorSubsystemVersion;
    DWORD Win32VersionValue;
    DWORD SizeOfImage;
    DWORD SizeOfHeaders;
    DWORD CheckSum;
    WORD  Subsystem;
    WORD  DllCharacteristics;
    DWORD SizeOfStackReserve;
    DWORD SizeOfStackCommit;
    DWORD SizeOfHeapReserve;
    DWORD SizeOfHeapCommit;
    DWORD LoaderFlags;
    DWORD NumberOfRvaAndSizes;
    IMAGE_DATA_DIRECTORY DataDirectory[IMAGE_NUMBEROF_DIRECTORY_ENTRIES];
} IMAGE_OPTIONAL_HEADER32;
  • BaseOfCode、BaseOfData 是代码/数据区域的 RVA 摘要，不是带基址的绝对地址；BaseOfData 仅见于 PE32，PE32+ 通常没有
  • 真正逐节的装载位置和大小仍由节表的 VirtualAddress、VirtualSize 决定，BaseOfCode/BaseOfData 不能替代

基址搬迁与重定位

模块内相对距离不因整体搬家改变。ImageBase=00400000h、RVA=2000h 时原地址为 00402000h；基址改成 00500000h 后同一 RVA 对应 00502000h，整体变化量 00100000h。代码中写死的绝对地址搬家后仍指向旧处：


mov eax, [00402000h]   ; 搬家后应修正为 mov eax, [00502000h]

大型程序不可能手工找所有绝对引用，PE 用重定位表批量修正：


重定位差值 = 实际加载基址 - 首选 ImageBase

ASLR 也会让实际基址与首选值不同；能否换址还取决于重定位信息、相关标志和系统策略。处理地址的顺序：

1. 先确认它是 VA、RVA 还是文件偏移 2. VA 减去实际模块基址得 RVA 3. 启用 ASLR 时不要把首选 ImageBase 当运行基址 4. 人为改 ImageBase 必须检查重定位表和所有基址相关绝对引用

注意：

  • 改 ImageBase 后只有基址相关的绝对引用需要修正；RVA 和相对寻址本身不因搬家改变
  • 打开随机基址位不保证一定随机加载，还要有可用重定位信息
  • 新增节通常不需要改 ImageBase，新节只是在映像末端安排新区域

对齐与镜像大小

PE 同时存在文件空间和内存空间，两种空间用不同对齐字段：

| 字段 | 作用 | 常见课堂值 | |---|---|---:| | FileAlignment | 文件中节原始数据的排列对齐（管磁盘） | 200h | | SectionAlignment | 节加载到内存后的 RVA 对齐（管内存） | 1000h |

SizeOfImage 是整个映像（头部加所有节）在内存中覆盖的范围，必须是 SectionAlignment 的倍数；SizeOfHeaders 是 DOS Stub、PE 头和节表按 FileAlignment 对齐后的头部范围。

文件按 200h 排列、内存按 1000h 排列时：


文件：0000h~01FFh PE 头 / 0200h~03FFh 代码节 / 0400h~05FFh 数据节
内存：RVA 0000h~0FFFh 头部页 / RVA 1000h~1FFFh 代码节 / RVA 2000h~2FFFh 数据节

这不是文件中 200h 字节"变成"1000h，而是实际复制的字节数与内存页覆盖范围不同。

下一节 RVA 与 SizeOfImage 计算


下一节 VirtualAddress
    = AlignUp(当前节 VirtualAddress + 当前节 VirtualSize, SectionAlignment)

SectionAlignment=1000h、第一节从 1000h 开始：

| 第一节 VirtualSize | 结束计算 | 第二节起点 | |---:|---:|---:| | 1800h | 1000h+1800h=2800h，向上对齐 | 3000h | | 0800h | 1000h+0800h=1800h，向上对齐 | 2000h | | 2000h | 1000h+2000h=3000h | 3000h |


SizeOfImage = AlignUp(max(每节 VirtualAddress + VirtualSize), SectionAlignment)

这比"把所有节大小简单相加"可靠。

注意：

  • 第二节起点不是固定 3000h，取决于第一节大小和对齐
  • VirtualAddress 是 RVA，不是带 ImageBase 的最终 VA
  • SizeOfImage 不是各 VirtualSize 相加，也不是单个节的字段；它必须至少覆盖所有节的映像末端，改小到覆盖不足会加载失败，改大只是预留范围
  • 异常布局中 SizeOfRawData 可能大于 VirtualSize，课堂公式是常见简化，需结合具体加载器判断

节表

节表是"文件到内存的搬运说明书"：每条 40 字节（28h）的节头告诉加载器这个节在文件哪里、放到内存哪里、占多大、什么权限。


typedef struct _IMAGE_SECTION_HEADER {
    BYTE    Name[IMAGE_SIZEOF_SHORT_NAME];
    DWORD   VirtualSize;
    DWORD   VirtualAddress;
    DWORD   SizeOfRawData;
    DWORD   PointerToRawData;
    DWORD   PointerToRelocations;
    DWORD   PointerToLinenumbers;
    WORD    NumberOfRelocations;
    WORD    NumberOfLinenumbers;
    DWORD   Characteristics;
} IMAGE_SECTION_HEADER, *PIMAGE_SECTION_HEADER;

| 字段 | 含义 | 关键注意 | |---|---|---| | Name[8] | 节名，如 .text、.data | 主要给人和工具看，不直接决定权限 | | VirtualSize | 节在内存中的有效大小 | 可大于原始文件数据，超出部分通常零填 | | VirtualAddress | 节在内存中的 RVA 起点 | 按 SectionAlignment 排列 | | SizeOfRawData | 节在文件中占用的原始数据大小 | 通常按 FileAlignment 对齐 | | PointerToRawData | 节在文件中的起始偏移 | 是 FOA，不是 RVA | | PointerToRelocations | 目标文件重定位信息位置 | 已链接普通 EXE/DLL 通常为 0 | | PointerToLinenumbers | 旧式行号信息位置 | 普通映像通常为 0 | | NumberOfRelocations | 重定位项数量 | 目标文件用途更多 | | NumberOfLinenumbers | 行号项数量 | 普通映像通常为 0 | | Characteristics | 节的代码/数据及读写执行属性 | 影响最终内存保护和运行 |

某节 VirtualAddress=1000h、VirtualSize=180h、PointerToRawData=200h、SizeOfRawData=200h，含义：


文件中：文件偏移 0200h 开始取 0200h 字节
内存中：从 ImageBase + 1000h 开始放置，有效内容前 0180h 字节

节内同一偏移 x 满足：


文件 FOA = PointerToRawData + x
内存 RVA = VirtualAddress + x

VirtualSize > SizeOfRawData 时，文件未覆盖的内存尾部由零填充，类似未初始化全局数据。

典型权限（课堂概念）：.text 可读可执行（RX）、.data 可读可写（RW）、.rdata 只读（R）。

注意：

  • 节名没有"编译器必加点"的硬规则，改名通常不影响加载，但程序、保护逻辑或分析工具可能依赖节名
  • Characteristics 不是装饰字段：去掉代码节执行属性代码无法执行，给数据节加执行属性改变安全边界
  • PointerToRelocations 等字段并非所有场景都没用，只是已链接的普通 EXE/DLL 通常为零

可选头其他字段与数据目录

可选头名叫"可选"，但对普通 EXE/DLL 的装载信息实际必需。

| 字段 | 更准确的理解 | |---|---| | Major/MinorOperatingSystemVersion | 映像声明的最低 OS 版本要求，改高系统可能认为环境不满足 | | Major/MinorImageVersion | 主要是版本元数据 | | Major/MinorSubsystemVersion | 与 Subsystem 共同描述期望的子系统环境 | | Win32VersionValue | 保留字段，普通映像通常为 0 | | SizeOfImage | 覆盖所有头和节的内存范围，按 SectionAlignment 对齐 | | SizeOfHeaders | 头和节表按 FileAlignment 对齐的范围 | | CheckSum | 普通 EXE 常不检查；驱动、启动阶段 DLL 等场景可能检查 | | Subsystem | 指定映像所需的子系统（控制台/窗口/驱动） | | DllCharacteristics | 多个按位标志的组合 | | SizeOfStackReserve/Commit、SizeOfHeapReserve/Commit | Reserve 是预留地址空间，Commit 是当前实际提交的内存 | | LoaderFlags | 保留字段，普通映像通常不用 | | NumberOfRvaAndSizes | 后面有效数据目录项的数量 | | DataDirectory[] | 每项提供一个位置（通常 RVA）和大小 |

栈提交默认约 4KB 是课堂常见示例，实际默认值与平台、链接器和映像有关。

DllCharacteristics 位掩码


0x0008  IMAGE_LIBRARY_THREAD_TERM       ; 原课堂文本名称，待核对/保留位
0x0020  IMAGE_DLLCHARACTERISTICS_HIGH_ENTROPY_VA
0x0040  IMAGE_DLLCHARACTERISTICS_DYNAMIC_BASE
0x0080  IMAGE_DLLCHARACTERISTICS_FORCE_INTEGRITY
0x0100  IMAGE_DLLCHARACTERISTICS_NX_COMPAT
0x0200  IMAGE_DLLCHARACTERISTICS_NO_ISOLATION
0x0400  IMAGE_DLLCHARACTERISTICS_NO_SEH
0x0800  IMAGE_DLLCHARACTERISTICS_NO_BIND
0x1000  IMAGE_DLLCHARACTERISTICS_APPCONTAINER
0x2000  IMAGE_DLLCHARACTERISTICS_WDM_DRIVER
0x4000  IMAGE_DLLCHARACTERISTICS_GUARD_CF
0x8000  IMAGE_DLLCHARACTERISTICS_TERMINAL_SERVER_AWARE
  • DYNAMIC_BASE 表示支持动态基址/重定位语义，但单独置位不保证 ASLR，还要看重定位表是否存在及系统策略
  • NX_COMPAT 表示兼容 DEP/NX，不等于"数据段一定不能执行"，具体页面权限由节 Characteristics 和系统策略决定
  • 这是位集合，可同时设置多个属性，不是互斥枚举

注意：课堂文本中的 IMAGE_LIBRARY_THREAD_TERM 0x0008 名称需以实际头文件核对；该低位在常见官方定义中属保留范围，不能据此推断出通用"线程终止属性"。

数据目录可能指向导入、导出、资源、重定位、TLS、延迟导入等结构；NumberOfRvaAndSizes 限制对目录的读取，避免越过真实可选头边界。详细表结构待下节课展开。

检查可选头的顺序：

1. 按 Magic 区分 PE32/PE32+，不要把 PE32 独有字段套到 PE32+ 2. 核对 ImageBase、两个对齐值、SizeOfHeaders、SizeOfImage 的互相约束 3. 版本字段问"声明的最低环境是什么"，不写"任意值" 4. DllCharacteristics 当位掩码逐位解析 5. 用 Reserve/Commit 语义检查栈堆参数 6. 用 NumberOfRvaAndSizes 限制 DataDirectory 读取范围
