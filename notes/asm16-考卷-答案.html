一、选择题答案

1. C - 20位（8086寄存器16位，但物理地址20位，通过段:偏移访问1MB空间） 2. B - 6字节（BIU的指令预取队列缓冲器） 3. C - JMP LABEL（跳转指令会清空预取队列，导致流水线断流） 4. C - CX（只有BX/BP/SI/DI可用于间接寻址） 5. B - CD 20（int 20h，DOS的容错机制） 6. C - CF（INC和DEC不影响进位标志CF） 7. B - AX（8位乘法：AX = AL × 源操作数） 8. D - AND AX, 0（这条指令确实能清零，所以题目可能有歧义。如果要选"不能"，应该是没有这样的选项，所有选项都能清零） 9. B - DS（MOVSB源地址DS:SI，目的地址ES:DI） 10. B - 0DBB0H（0DAB × 10h + 0100 = 0DBB0H） 11. A - NOP（机器码90H，单字节） 12. A - 将AL符号扩展到AX（CBW = Convert Byte to Word） 13. B - ZF（TEST执行AND运算但不写回，结果为0则ZF=1） 14. C - CX（LOOP指令隐含使用CX作为计数器） 15. D - 以上都不可以（CS只能通过跳转指令修改，不能作为MOV/POP的目的操作数；PUSH CS可以）

三、判断题答案

1. × - 同一物理地址可对应多个逻辑地址（如0000:0100和0010:0000都指向00100H）

2. × - MOV不能内存到内存直接传送，必须通过寄存器中转

3. √ - PUSH/POP以字（16位）为单位，SP每次变化±2

4. √ - JMP是控制转移指令，不影响标志位

5. × - CMP执行减法但不保存结果，只影响标志位

6. × - LODSB不改变标志位，需要手动OR AL, AL或TEST AL, AL

7. × - LEA只计算地址值，不访问内存

8. × - IN/OUT访问I/O端口地址空间，不是内存地址空间

9. × - HLT是硬件级挂起，等待中断唤醒，不是死循环

10. × - 8086实模式没有Ring概念，所有代码权限相同（Ring是286+保护模式引入的）

四、简答题答案

1. JMP NEAR和JMP AX的区别

段内直接转移（JMP NEAR）：

  • 机器码中编码相对偏移量（-32768~+32767）
  • 汇编器计算：新IP = 当前IP + 相对偏移
  • 具备位置无关性（PIC）
  • 使用场景：固定的跳转目标，如if/else、循环

段内间接转移（JMP AX）：

  • 目标地址从寄存器或内存读取
  • 机器码不包含目标地址
  • 运行时动态决定跳转目标
  • 使用场景：函数指针调用、Switch-Case跳转表

2. 为什么编译器更喜欢XOR清零

相同点： 两者都能将AX清零，对标志位的影响相同

XOR的优势： 1. 机器码更短：XOR AX, AX是2字节（31 C0），SUB AX, AX也是2字节，但MOV AX, 0是3字节（B8 00 00） 2. 执行更快：XOR不需要从内存/指令流读取立即数，直接在寄存器内部操作 3. 通用模式：编译器统一用XOR清零所有寄存器，简化代码生成逻辑

3. 为什么有符号除法前必须符号扩展

原因： 16位除法DIV/IDIV的被除数是32位（DX:AX）

  • 如果AX是负数（如-10 = FFF6H），DX必须是FFFFH才能正确表示-10
  • 如果不扩展，DX可能是垃圾值，导致被除数错误

CWD的作用：

  • 检测AX的最高位（符号位）
  • 如果AX最高位=0（正数），DX=0000H
  • 如果AX最高位=1（负数），DX=FFFFH

不扩展的后果：

  • 例如：AX=-10（FFF6H），DX=0000H（未扩展）
  • 被除数 = 0000FFF6H = 65526（正数！）
  • 除以3得商21842，完全错误

4. MZ和COM文件格式的区别

| 对比项 | COM格式 | MZ格式 | |--------|---------|---------| | 文件头 | 无文件头，纯机器码 | 有IMAGE_DOS_HEADER（至少64字节） | | 内存模型 | 单段模型，CS=DS=SS=ES | 多段模型，代码/数据/栈分离 | | 入口点 | 固定0100H（前256字节PSP） | 由e_cs和e_ip指定，灵活 | | 体积限制 | 严格≤64KB | 突破64KB限制 | | 重定位 | 无重定位机制 | 有重定位表，支持动态加载 | | 加载地址 | 固定加载到可用段+0100H | 操作系统动态分配基址 |

五、代码阅读题答案

1. 机器码解析

  • 对应的汇编指令： ADD BX, 7FH
  • opcode是： 83（带符号扩展的ADD）
  • ModR/M字节是： C3（二进制11 000 011，mod=11寄存器寻址，reg=000，r/m=011=BX）
  • 立即数是： 7FH（127）
  • 这条指令使用了符号扩展吗？ 是（S=1，1字节立即数符号扩展为16位）

2. 代码段分析

这段代码的功能是： 在BUFFER指向的内存区域中查找字符'A'，最多搜索10个字节

CX寄存器的作用是： 循环计数器，控制LOOP指令的重复次数（10次）

如果改用REPNE SCASB实现，需要修改：


MOV CX, 10
MOV DI, OFFSET BUFFER    ; 改用DI，因为SCAS使用ES:DI
MOV AL, 'A'              ; 要查找的字符放AL
CLD
REPNE SCASB              ; 不等则继续，找到'A'时停止
JNZ NOT_FOUND            ; 如果CX=0且没找到
DEC DI                   ; DI回退到匹配字符（SCAS会自动+1）
FOUND:

六、编程题答案


; 将DS:SI的10字节复制到ES:DI

CLD                      ; 设置方向标志为正向（DF=0）
MOV CX, 10              ; 设置复制字节数
REP MOVSB               ; 重复执行MOVSB，CX次

; 或者优化版本（按字传送，快一倍）：

MOV CX, 5               ; 10字节 = 5个字
REP MOVSW               ; 按字传送

评分标准：

  • CLD指令（2分）
  • MOV CX, 10（2分）
  • REP MOVSB（6分）
  • 如果使用MOVSW优化，额外加分

七、综合分析题答案

1. 这段代码使用了什么反逆向技术？（2分）

答： 花指令（Junk Code）技术，通过插入脏字节（0B8H）破坏反汇编器的指令边界识别。

2. 线性扫描反汇编器的错误解析（3分）


; 反汇编器错误地解析为：
JMP SHORT LABEL1        ; EB 01
MOV AX, 3412H           ; B8 34 12（错误！把脏字节B8当成了MOV的操作码）
; 后续指令全部错位变成乱码

解释： 线性扫描从入口点逐字节解码，不理会控制流。它把0B8H当成MOV AX, imm16的操作码，吞噬了后续的34 12作为立即数，导致真正的MOV AX, 1234H被错位解析。

3. CPU实际执行（2分）

答： CPU执行JMP SHORT LABEL1后，IP直接跳过脏字节0B8H，落在LABEL1标号处，正确执行MOV AX, 1234H和ADD AX, BX。脏字节永远不会被执行。

4. 如何清除花指令（3分）

方法： 1. 识别永真跳转：确认JMP SHORT LABEL1必然跳转，脏字节0B8H永远不会执行 2. 手动打NOP：在调试器（如x64dbg）中将0B8H替换为90H（NOP） 3. 重新分析：让反汇编器按修正后的字节流重新分析

或使用自动化方法：

  • 编写IDAPython脚本识别"短跳转+单字节"模式
  • 自动将脏字节标记为数据（DB）而非代码
  • 批量处理大量花指令块
